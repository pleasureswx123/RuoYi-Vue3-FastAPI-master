# Shot Grid 桌面版本发布

首次上线时，通过项目现有生产发布流程部署 Shot Grid 前端的 Nginx 配置和 Compose 只读目录挂载。然后发布 V0.1.10，向仍在使用旧版的同事分发一次 V0.1.10 安装包。此后的版本由桌面端检查并提示。

## 发布人员

在持有签名密钥的 Windows 打包账号下，从仓库根目录执行。示例将安装包版本设为 V0.1.11，构建后签名并通过 SSH 上传。

```powershell
.\deploy\publish-desktop.ps1 -Version 0.1.11 -Notes '优化镜头列表的点击响应。'
```

加 `-BuildOnly` 可只构建本地安装包和签名清单，文件位于 `shot-grid-frontend/src-tauri/target/release/bundle/nsis/`。验收后，使用相同版本、相同说明并加 `-UseBuiltInstaller` 发布刚验收的安装包。每次正式发布使用递增的三段数字版本号。

服务器将安装包保存在 `/var/lib/ruoyi-shot-grid/desktop-updates/<版本号>/ShotGrid-setup.exe`，该目录的 `release.json` 保存签名记录。上传校验通过后，发布脚本原子替换上级目录的 `latest.json`。客户端只访问内网端口 12581，日常发布桌面版本无需重启后端或操作管理页面。

## 签名密钥

打包机的 `%LOCALAPPDATA%\ShotGridRelease\signing-key.dpapi` 由当前 Windows 用户的 DPAPI 保护，桌面端内置对应公钥。签名覆盖版本号、更新说明和安装包 SHA-256。发布人员应按公司密钥备份流程保管可恢复的私钥；仅复制 DPAPI 文件到新机器不足以恢复。更换公钥前需先用原密钥发布带新公钥的过渡版本。

## 使用者

进入制作平台后，左上角显示本机版本。桌面端启动时检查更新，也可点击右上角的「检查更新」。出现新版本时可稍后处理，也可下载并在保存工作后确认安装。安装成功后重新打开工作台，桌面快捷方式随安装升级。内网不可达时仍可打开客户端，通过手动检查可查看连接错误。
