# 镜头与资产强制删除：永久删除设计

状态：用户已确定产品语义，待本设计评审；尚未实现。

## 已确定的用户意图

2026-10-13 用户补充：用途是清除有问题的镜头或资产，彻底删除完成后以同一镜头号或资产名称重新创建。删除 NAS 文件是为了避免重新上传与旧文件冲突。成功标准必须是“旧业务与独占文件彻底清理 → 释放编号/名称对应路径占用 → 同编号/同名新建 → 新上传成功”，不能只证明删除动作被接收。

清理未完成或失败时显示明确状态，并阻止复用相同路径；不能让用户先新建后才在上传时遇到旧文件。清理成功后应允许在原作用域复用原镜头号或资产名称，生成新的实体 ID，且不能继承旧任务、版本计数或旧文件引用。共享资源保留不代表允许残留目标独占的上传文件；如共享关系妨碍安全释放目标路径，必须明确阻止并说明，不能假报完成。

沿用当前“强制删除镜头”“强制删除资产”按钮及各自 forceDelete 权限。强制删除就是永久删除，不增加删除模式、额外按钮或第二套权限。删除目标的业务历史和独占 NAS 文件；不删除其他目标共用资源。保留最小删除审计，不保留可浏览的被删业务历史。

## 当前代码事实

- ForceDeleteService / ForceDeleteDao 当前仅逻辑删除目标和任务，保留版本及 NAS；不能仅改弹窗文字宣称永久删除。
- ProjectPurgeService / ProjectPurgeDao / ProjectPurgeWorkerService 已提供项目级业务图删除、独立清理队列、租约和文件清单。其路径与范围是整个项目，不能直接用于单个镜头或资产。
- 文件服务通过 SysFileReference 维护业务引用；NAS 版本路径由 sg_version_file 等记录维护。删除归属必须核对数据库引用及路径，不能仅按名称推导目录。

## 接口与权限

保持既有 batch-force-delete 路由和当前权限、项目管理范围、项目生命周期、目录迁移、lockVersion 校验。沿用必填删除原因及显式最终确认，弹窗清晰标注“不可恢复”。不另加确认模式。

返回保留 deletedShotIds / deletedAssetIds 与 deletedCount，新增清理记录 ID 与清理状态；接收成功只表示业务删除已提交，不能显示 NAS 已全部清除。提供同项目范围的清理状态查询及失败重试接口，重试仍要求对应 forceDelete 权限。

## 数据删除范围

- 镜头：目标镜头、该镜头全部任务（含历史逻辑删除任务）、排期历史、提交与提交文件关联、版本轮次、候选、版本文件关联、媒体派生、最终交付、专属审核单及审核动作、问题及回复、参考文件引用、镜头资产关系、目标镜头需求。
- 资产：父资产、全部制作分项（含归档和逻辑删除分项），以及各分项上述完整业务图。其他镜头保留，其对被删资产的关系解除；其他镜头需求保留并解除资产匹配。
- 混合人工审核单只移除被删版本及其专属记录；保留其他目标，空单删除。不得因共享审核单跨目标删除。
- 共享导入批次等项目级记录不整批删除；清除其被删目标的专属引用，其他目标信息保留。
- 删除审计与清理队列独立于业务外键，保留操作者、时间、原因、目标标识、清理清单和结果，不保存原业务内容全文。

实施时逐表核对真实外键及文件 business_type 映射，完成范围清单和测试后才能落地删除 SQL。

## 事务与并发

在项目协调锁内重新校验权限、成员身份、目标及版本，锁定目标相关运行任务。对正在执行真实 I/O 的目标拒绝本次提交并提示稍后重试，不能只使回写失效就立即删目录：旧 I/O 仍可能重新创建文件。所有写入/领取路径必须识别已删除目标及清理路径占用。

一个事务内生成不可变路径和文件清单、写入独立清理记录、移除对应引用及业务图、写最小审计；失败整体回滚。事务中不等待 NAS。

使用独立目标清理表，通过 PostgreSQL Alembic 新版本接续当前实际 head，并同步初始化 SQL。清理记录不依赖已删除目标存在。为待清理路径保留占用标识，直到清理完成前阻止新对象复用；旧清理任务不能误删后来创建的新对象。

## 后台文件清理

沿用项目级清理的 Leader、短事务、SKIP LOCKED、租约、心跳、owner + attempt fencing 机制，但使用目标级路径适配及任务范围。

仅清理经证实由目标独占的 NAS 目录及文件，不清理项目根、场次根、资产类型根或其他共享父目录。删除前校验存储根、实际 CIFS/SMB 挂载、路径边界和链接；路径归属不明确则标记失败，不扩大范围。平台文件只有无其他业务引用且符合保留策略时才清理；共享文件仅移除本目标引用。

路径不存在视为幂等成功，连接或权限错误进入可重试状态。清理途中失败可从剩余清单继续。未启用 Worker 时必须显示等待清理，不能宣称完成。项目整体删除与目标清理需协调，避免相同路径被不同队列并发处理。

## 前端体验

原行内按钮、位置和原因弹窗不变。提示改为永久删除当前镜头/资产及制作历史、独占文件且不可恢复；资产说明包括制作分项。删除后移除列表记录，明确显示“业务记录已删除，文件清理中”，并提供该操作的清理进度/失败重试反馈。不得提示“保留历史和 NAS 文件”。继续保持弹窗不因滚动条宽度和表格自动列变化而消失。

## 验证与交付

- 隔离 PostgreSQL：全阶段业务图、历史逻辑删除记录、共享审核单/引用保护、跨项目与错误权限拒绝、乐观锁、事务回滚、迁移升降级。
- 文件适配器：目标边界、共享目录、链接、错误挂载、目录缺失、部分失败重试、同名重建隔离。
- 并发：旧 Worker 正在写入时拒绝、新领取与删除互斥、失租不回写、重复清理幂等、项目清理协调。
- 前端：永久删除提示、校验、处理中与失败反馈、原行内弹窗稳定性。
- 真实浏览器只验证确认界面和状态展示，不删除用户已有业务。真实 NAS 清理只能使用单独创建且明确可丢弃的测试目标；未运行必须如实报告。

升级前备份。代码/迁移降级不能恢复已永久删除的业务和文件，恢复需要升级前的数据库与文件备份。此前已经逻辑删除的历史目标不自动追溯清理，本变更仅作用于上线后明确提交的强制删除。

## 实施对齐补充

路径占用属于 PostgreSQL 兼容扩展：除服务层提示外，迁移在镜头和资产身份写入处增加数据库门禁，覆盖导入和批量重编号；门禁使用项目行锁，与删除事务协调。同项目其他路径仍可写入。未完成清理期间，涉及共享父目录的重编号和存储迁移拒绝执行。此扩展不承诺 MySQL。
