一、先读结论
本包是当前工作区源码快照，包含本次镜头、资产、制作工作台及每日多平台记录优化。不是免配置安装包，不是与同事仓库的精确补丁，也不是正式上线验收结论。
同事应在自己的仓库建立交接分支，解压到独立位置比对合并，禁止直接覆盖现有生产代码、环境文件或数据库。
最新版产品依据是包内 output/ShotGrid需求梳理与新旧流程对照-图文交接版-管理员与制作人员补充-20261112.docx（25页）。本说明负责源码接入和验收交接；图文文档负责产品需求与界面。
当前交接工作区没有 .git，不能提供可靠的原始提交基线、提交历史或完整新旧代码差异。包内提供逐文件 SHA-256 清单用于核对传输完整性。

三、最终产品规则与历史文档冲突处理
1. 进入工具先选项目，镜头、资产及工作台保持当前项目范围；制作人员可浏览项目全貌，不能因此修改或代交他人任务。
2. 镜头和资产制作分项分配有效制作人后自动准备目录，不需要额外确认开工、强制排期或完善所有信息。目录准备成功、本人提交和权限校验仍必须保留。
3. 镜头待审核时允许继续提交新轮次；完成后可正式打反馈重新进入修改。普通评论不改变任务状态。资产同轮追加与镜头新轮策略尚有差异，不能未经核对宣称完全统一。
4. 镜头紧凑可编辑表格、列宽/行高、筛选与批量反馈/周期/分配；成果、版本反馈和制作参考集中右侧，不恢复大面积底部预览。
5. 资产保持大项/制作分项、独立负责人和版本；关联资产用于制作参考，不能变成强制开工审批。
6. 制作人“我的任务”同时列出镜头和资产；提交、参考、反馈和每日记录就近可达。
7. 版本目录按镜头或资产分项隔离，FINAL位于通过版本目录内；历史成果保留。当前文件夹演示采用本地模拟，正式NAS另行接入验收。
8. 每日记录与成果提交独立；同任务可多平台一次保存。积分按平台分开，实际0有效；无实际值才估算。不要增加日报审核或强制截图。
9. 本周/上周/本月/上月及自定义范围汇总；生成量、提交轮次、期间曾通过任务分别计算，不能因多平台记录重复计数。
根AGENTS、早期README和旧契约可能仍有“管理人确认开工”“排期重叠二次确认”等旧描述。最新产品决定见图文文档，实施记录见 shot-grid-frontend/AGENTS.md 与 ruoyi-fastapi-backend/AGENTS.md 末尾10月至11月追加内容。合并时核对实际源码并统一旧文档，不要恢复用户已取消的步骤。权限、事务、文件安全、目录发布和迁移约束继续有效。

五、数据库接入与迁移
主数据库为PostgreSQL。当前源码迁移链最后版本为20261111_43（每日记录），前置20261102_42（资产关联）、20261030_41（反馈评论）。本包不导出或改动任何数据库。
已有同事数据库：先备份并恢复到隔离克隆库；安装依赖、配置克隆库连接后执行 python -m alembic current 与 python -m alembic heads，比对迁移历史和实际表结构，再执行 python -m alembic upgrade head。完成验证后才评审正式升级。
没有版本标记的历史库：不能直接stamp head，也不能不检查就执行增量迁移。
真正空库：平台尚无完整Alembic空库baseline，需先用已同步的PostgreSQL初始化SQL建平台表，并核对平台/Shot Grid结构与head完全一致，再记录对应版本。不可把导入最新SQL和重跑全部历史DDL叠加。具体初始化与stamp流程必须先在空测试库验证。
开发Compose的postgres仅在新数据卷首次创建时执行初始化SQL；已有卷不会自动补结构。禁止为升级而删除旧卷。
新增每日记录权限：shotgrid:daily:write 与 shotgrid:daily:stats。升级后重新登录刷新菜单与权限；统计还需项目管理范围，不能只放开前端菜单。

六、同事本地启动顺序
环境：Node >=22.13.0、npm、Python建议3.11、PostgreSQL、Redis。媒体派生启用时还需FFmpeg。
先查看本机是否已占用5174、9099、15432、16379；不要停止其他项目服务。
1）在解压根目录：docker compose -f docker-compose.dev.yml up -d postgres redis
   仅启动依赖；不要同时启动Compose后端和宿主机后端。若使用自己的数据库/Redis，跳过此步，填写实际连接。
2）后端目录创建虚拟环境并安装：
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install -r requirements-pg.txt
   python -m pip install -e .
3）复制包内后端 .env.dev.handoff.example 为 .env.dev，填写本地数据库、Redis、JWT及加密配置。模板只有占位值，不能直接启动。生成传输密钥可先运行 ruoyi crypto keygen --help，再按本机CLI输出配置密钥；私钥不要发到聊天、提交仓库或写进交接报告。
   不要通过关闭验证码、移除Redis或降低加密模式掩盖启动问题。公司固定内网HTTP例外不能扩展到其他部署。
4）按第五节核对/升级数据库。执行 ruoyi app doctor --env=dev，排除数据库、Redis和加密配置问题，再执行 ruoyi app run --env=dev。也可按现有README使用uvicorn运行工厂，端口9099。
5）另开终端进入 shot-grid-frontend：复制 .env.development.handoff.example 为 .env.development，执行 npm.cmd ci，再 npm.cmd run dev。
   访问 http://127.0.0.1:5174；/dev-api代理到9099。确保 /captchaImage 返回图片，登录后 /getInfo、导航和项目列表可用。
6）平台用户、固定角色包、项目成员及存储根通过现有平台功能配置。平台管理前端属于 ruoyi-fastapi-frontend；其依赖安装与启动按本目录package.json执行，不要误把管理端当成本次优化业务端。
本机历史验证码故障来自PostgreSQL未启动导致接口超时；排查顺序为DB、Redis、后端接口、前端代理，再看页面。
模板默认不启用真实存储/版本/媒体Worker，防止未经配置执行NAS I/O。完成真实上传必须另外配置存储适配与对应Worker；仅启动页面不能证明提交流程完成。

七、本地模拟文件夹与正式NAS
本地打开器是用户级Windows协议工具，安装会注册HKCU协议，并在LOCALAPPDATA生成程序。先读脚本，使用 -Mode Test 进行自检；安装和卸载按脚本头部说明。测试同事需单独配置自己的模拟根目录。
本地打开器演示与后端真实版本发布是不同环节，不要把“模拟文件夹能打开”报告为NAS交付成功。
镜头：项目名/SHOT/集/场次/镜头号/V001/成果文件。
资产：项目名/ASSET/类型/资产名/制作分项名称及稳定ID/V001/成果文件。
通过：对应V001或V002目录内的FINAL保存选定成果；JSON清单可隐藏但不能删除校验和审计资料。
正式NAS需另行收集共享路径、客户端访问情况和服务账号权限，凭据通过安全渠道交接，不写入本包。延续现有路径白名单、鉴权、文件引用、SHA-256与Worker租约/fencing约束。
