# 中危依赖逐项核查与定向回归（2026-11-17）

## 结论与范围

本次原有 6 项生产依赖中危告警，实际来自 3 个底层问题，上层依赖被连带计数。管理端修复 4 项，生产依赖审计为 0；Shot Grid 保留 ExcelJS / UUID 2 项中危，未伪造零告警，也未认定所有上线门禁已通过。

仅修改工作分支代码及本地验证环境。未合回 main、推送或部署；未修改原数据库、原 NAS 项目文件或离线备份。使用卢清华现有权限进行浏览器验收，没有使用 admin 或扩大账号权限。`.env.dev` 是此前的本地修改，本次未修改或提交。

## 逐项核查

| 告警项 | 通俗说明与当前使用位置 | 本次处理 |
| --- | --- | --- |
| minimatch | 按文件名模式找文件的工具。特定恶意模式在优化时可能消耗大量资源，让处理变慢。管理端经 EditorConfig 间接使用。 | 仅在 js-beautify → editorconfig 范围内固定为 11.0.5。 |
| glob | 扫描匹配文件的工具。旧版取消扫描时可能未真正停止，继续消耗资源。 | 仅在 js-beautify 范围内固定为 14.0.6。 |
| editorconfig | 读取缩进等代码格式配置，自身被计数是因为依赖有问题的 minimatch。 | 保留当前 API，通过上述子依赖修复解除告警，验证真实配置解析。 |
| js-beautify | 管理端表单设计生成 Vue 代码时负责排版。因为带入上面两个工具而连带告警。 | 保留 1.15.4，采用局部 overrides，不盲目升级主版本。实际格式化函数与配置未改。 |
| uuid | 生成标识符的工具。公告针对 v3/v5/v6 在调用者传入输出缓冲区时缺少边界校验。 | 保留告警，原因见下。当前 ExcelJS 源码使用的是 v4，尚未发现本项目调用公告中的受影响入口。 |
| exceljs | Shot Grid 用它预览 XLSX、导出每日记录等 Excel 内容，因为依赖旧 UUID 被连带计数。 | 保留 4.4.0；未将审计建议的跨主版本降级作为安全修复。 |

## 为什么暂时保留 ExcelJS 的两项告警

ExcelJS 4.4.0 的 `browser` 字段指向预先打包的 `dist/exceljs.min.js`，其中已包含旧 UUID。单独在 package.json 中覆盖 UUID，即使 npm audit 不再报告，也不能证明浏览器产物中的代码已更新。

当前源码在 `lib/xlsx/xform/sheet/cf-ext/cf-rule-ext-xform.js` 中使用 `v4` 生成条件格式标识，与公告涉及的调用方式不同。这降低了当前已知业务路径的可触发风险，但不等于依赖问题已经修复。

已在 `.git/dependency-audit-20261117/excel-probe/` 做独立实验：ExcelJS 4.4.0 + UUID 11.1.1 + Browserify 17.0.1。重打包遇到 UUID 新语法解析失败，而且引入的打包工具链另有 4 项低危关联告警。实验未进入业务代码。自维护浏览器包并非不可能，但需要单独维护打包兼容、浏览器依赖和 XLSX 行为，本次没有足够证据把它认定为可安全直接替换。

后续优先核查 ExcelJS 正式更新的浏览器产物；若必须消除这两项告警，再安排受控重打包或替代库专项，覆盖公式缓存、多工作表、条件格式、导入与导出。不能仅凭审计计数下降放行。

1. `npm run test:dependencies`：新增 2 项测试全部通过，验证中文 Vue 内容、绑定表达式、重复格式化稳定性，以及真实 js-beautify CLI 使用 glob 与 EditorConfig 处理嵌套文件。Windows Node 24 与隔离容器 Node 22 均通过；已加入管理端 CI。
2. `npm run test:plugin`：隔离容器中通过 1 项插件解析测试。
3. `npm run build:prod`：使用更新后的管理端 package.json / package-lock.json 在隔离容器中构建通过；仍存在既有大包与第三方 PURE 注释警告，未提高告警阈值。
4. `npx vitest run tests/unit/referencePreview.spec.js`：通过 3 项，覆盖 DOCX、XLSX 多工作表和公式缓存，以及 TXT/PPTX 解析。宿主机执行较慢，随后隔离容器也确认通过。它属于解析测试，不代表浏览器 XLSX 预览完整 E2E。
5. 内置浏览器实际操作：使用修复后依赖和项目 `beautifierConf` 的专用测试页，点击“格式化 Vue 示例”成功，中文和绑定保留，再点击“验证重复格式化”显示一致。卢清华没有表单设计菜单权限，因此该项是格式化组件浏览器验证，不是完整表单设计页面 E2E。
6. 内置浏览器实际业务操作：卢清华登录 `http://127.0.0.1:5674/shot-grid-app/`，进入隔离项目“上线前独立功能验收20261117”的每日记录，点击“导出 Excel”，真实下载文件。回读结果为 1 条记录：任务 EP001-001-0010、生成量 3、实际积分 0，中文备注与页面一致。没有新增或修改业务记录。Shot Grid 本次未修改依赖，验证的是当前保留版本的导出功能。
7. 最终 `npm audit --omit=dev --json --registry=https://registry.npmjs.org`：管理端 0；Shot Grid 中危 2、高危 0、严重 0。本结论仅针对生产依赖，不表示开发依赖也为零。
