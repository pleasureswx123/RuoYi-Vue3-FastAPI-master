# Shot Grid MVP 部署说明

## 0. 构建环境与依赖安装

发布基线使用 **Node.js 20.20.2** 和 **npm 11.4.2**。`package.json` 与
`package-lock.json` 是同一份依赖契约；发布机和 CI 必须在
`shot-grid-frontend/` 目录使用锁文件进行干净安装：

```bash
rm -rf node_modules
npm ci
npm run lint
npm test
npm run build:prod
```

`lint`、`test` 和 `build:prod` 必须作为三个独立命令执行。生产构建产物位于
`shot-grid-frontend/dist/`，发布时将该目录部署到站点的 `/shot-grid/` 路径。

当前直接依赖版本已经在 manifest 与锁文件中对齐：Axios 1.19.0、Vue
3.5.26、Element Plus 2.14.3、Pinia 3.0.4、Vue Router 4.6.4、Vite
6.4.3，以及 Sass 实现 `sass-embedded` 1.97.2。不得仅修改其中一个文件；
依赖升级后应重新生成锁文件并再次执行 `npm ci` 验证。

### 0.1 npm 代理配置

npm 支持标准的 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量，也可以使用 npm 的
`proxy` 与 `https-proxy` 配置项。例如：

```bash
npm config set proxy http://proxy.example.internal:8080
npm config set https-proxy http://proxy.example.internal:8080
```

若通过环境变量注入 npm 配置，请使用 `npm_config_proxy` 和
`npm_config_https_proxy`。不要使用已失效的 `npm_config_http_proxy`；npm
11 会将它解析为未知的 `http-proxy` 配置并输出
`Unknown env config "http-proxy"`。该变量通常来自 CI、容器或终端启动脚本，
应在相应环境配置中删除，而不是写入项目 `.npmrc`。可用以下命令定位来源：

```bash
env | grep -iE '(^|_)npm.*proxy|^https?_proxy'
npm config list --long
```

## 1. 已冻结拓扑

MVP 采用**同域、不同路径、同一后端**：

```text
https://example.internal/admin/      -> 管理端独立 SPA
https://example.internal/shot-grid/  -> Shot Grid 独立 SPA
https://example.internal/api/        -> 同一个 RuoYi FastAPI 后端
```

两个前端拥有独立入口、路由基址和构建产物，不互相导入运行时代码。Shot Grid 自带登录页面，但认证能力完全复用平台 `/login`、`/getInfo`、`/logout`、Redis 会话与 Bearer Token；不部署第二个认证服务，不创建业务账号表。

## 2. 会话决策

| 项目 | MVP 决策 |
| --- | --- |
| 存储 | `js-cookie` Cookie `Admin-Token`，`Path=/`，两个 SPA 共享 |
| 请求 | `Authorization: Bearer <Admin-Token>` |
| 刷新 | 读取 Cookie，调用 `/getInfo`，成功后恢复原目标路由 |
| 主动退出 | 调用 `/logout`，无论响应结果均清 Cookie 与应用内身份缓存 |
| 401/过期 | 合并并发提示；用户确认后执行同一退出清理，回本应用登录页 |
| 跨应用跳转 | 仅普通同域链接；URL、查询串、fragment、`postMessage` 均不携带 Token |

由于当前 Cookie 不是 HttpOnly，共享会话扩大了两个 SPA 的共同 XSS 影响面。因此该方案只适用于同一组织控制、相同安全等级的同域应用；两套静态资源必须执行相同 CSP、依赖审计和发布门禁。若未来业务端成为不同信任边界，必须改为不同存储键并独立登录，不能用前端脚本交换 Token。

## 3. API 前缀矩阵

| 环境 | 页面入口 | 浏览器 API 前缀 | 后端 `APP_ROOT_PATH` | 代理行为 |
| --- | --- | --- | --- | --- |
| 开发 | Vite 各自端口 | `/dev-api` | `/dev-api` | Vite 剥离 `/dev-api` 后转发 |
| 生产 | `/admin/`、`/shot-grid/` | `/api` | `/api` | Nginx 剥离 `/api` 后转发 |
| Docker | `/admin/`、`/shot-grid/` | `/docker-api` | `/docker-api` | Nginx 剥离 `/docker-api` 后转发 |

**强制不变量：**浏览器所见路径、FastAPI `root_path` 和代理转发路径必须形成唯一、可验证的映射。代理剥离外部前缀后把真实路由转发给应用，`APP_ROOT_PATH` 则声明被剥离的外部前缀，供 OpenAPI、鉴权与传输加密路径规范化使用。不得既保留前缀转发又让应用按无前缀路由注册，也不得重复剥离。同一个后端实例只有一个 `APP_ROOT_PATH`，所以两个前端不能使用不同的 API 前缀访问该实例。

领域路由始终是后端 `/shot-grid/...`；例如生产浏览器请求 `/api/shot-grid/projects`。登录为 `/api/login`。公开传输加密接口为 `/api/transport/crypto/frontend-config` 和 `/api/transport/crypto/public-key`。

## 4. Nginx 参考配置

```nginx
location /admin/ {
    alias /usr/share/nginx/html/admin/;
    try_files $uri $uri/ /admin/index.html;
}

location /shot-grid/ {
    alias /usr/share/nginx/html/shot-grid/;
    try_files $uri $uri/ /shot-grid/index.html;
}

location /api/ {
    proxy_pass http://ruoyi-backend:9099/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

生产后端设置 `APP_ROOT_PATH=/api`。Docker 将上例的 `/api/` 同步替换为 `/docker-api/`，并设置 `APP_ROOT_PATH=/docker-api`。`proxy_pass` 末尾的 `/` 用于剥离 location 前缀，必须保留。

## 5. Swagger 与传输加密核对

部署后逐项检查：

- Swagger、ReDoc、OpenAPI 分别能通过 `{API_PREFIX}/docs`、`{API_PREFIX}/redoc`、`{API_PREFIX}/openapi.json` 访问，生成的 Server URL 不重复也不遗漏前缀。
- `/transport/crypto/frontend-config` 和 `/transport/crypto/public-key` 经同一 API 前缀匿名访问，限流和缓存仍生效。
- Shot Grid 的传输加密实现对齐管理端：在请求参数拼接前加密；AAD 中的 path 是移除外部 API 前缀后的真实后端路径；加密错误响应先解密；公钥失效只清缓存并重试一次。
- 登录、上传、下载和二进制接口继续遵守后端公开策略及排除规则，不能由 Nginx 单独改写业务路径绕过策略匹配。

## 6. 发布与验收

1. 分别构建并发布管理端和 Shot Grid，确认 HTML fallback 只回到各自的 `index.html`。
2. 验证两个 SPA 都只请求同一个 API Origin 和前缀。
3. 执行 `领域模型与API契约.md` 20.0 节全部认证用例，并保留浏览器网络记录；必须覆盖登录成功、刷新恢复、Token 过期、两类 401、主动退出和双向跨应用跳转。
4. 再执行角色、项目成员与领域权限用例。共享登录态不代表共享页面权限，管理端继续使用平台菜单/接口权限，Shot Grid 继续使用平台权限与项目成员权限交集。

当前 `shot-grid-frontend/` 已有 Vue 3/Vite 可运行工程；但在真实前后端、PostgreSQL、Redis 与 Nginx 未共同启动并执行浏览器业务链前，不得声称上述 E2E 已通过。
