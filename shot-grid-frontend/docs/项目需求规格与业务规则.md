## 2. 产品目标与系统边界

### 2.1 产品目标

系统用于管理 AI 影视短片从项目建立到镜头、资产制作与审核完成的协作过程，重点解决：

1. 项目总监统一建立项目、集、场次、镜头和资产；
2. 将镜头视频任务和资产图片任务分配给制作人员；
3. 制作人员在线下制作，在平台上传产出物；
4. 每次上传形成不可覆盖的版本和对应审核单；
5. 项目总监或管理员基于具体版本提出意见、退回修改或确认最终版；
6. 所有成员通过项目权限访问同一套业务数据和 NAS 项目目录；
7. 项目概览提供统一、可追溯的进度统计。

### 2.2 核心业务主线

```text
项目
├── 集
│   └── 场次
│       └── 镜头
│           └── 唯一镜头视频任务
│               └── 版本 V001...Vnnn
│                   └── 每版本一个自动审核单
└── 资产（角色/场景/道具）
    └── 制作分项（一个或多个）
        └── 唯一资产图片任务
            └── 版本 V001...Vnnn
                └── 每版本一个自动审核单
```

### 2.3 平台负责

- 项目、项目成员及项目内角色管理；
- 集、场次、镜头、资产的创建、导入、查询和维护；
- 任务分配、改派、状态跟踪和个人工作台；
- 图片、视频产出物上传和版本管理；
- 自动审核单、审核意见、审核动作和最终版本确认；
- NAS 项目目录初始化、路径登记、权限内展示和文件落位；
- 项目进度统计、审计和站内通知。

### 2.4 平台不负责

- 在线生成图片或视频；
- 在线剪辑、调色、混音或工程文件编辑；
- Premiere、达芬奇、After Effects 等桌面软件插件；
- 制作人员本地工程目录和中间素材管理；
- 工时、预算、成本结算和复杂排期；
- 匿名外链、客户门户和外部审核；
- AI 自动拆本、自动审核或自动生成提示词。

## 3. 业务术语与层级

| 术语 | 英文/代码 | 定义 |
| --- | --- | --- |
| 项目 | Project | 一部 AI 影视短片的业务和权限边界 |
| 集 | Episode | 项目下的分集实体 |
| 场次 | Scene | 一集内的叙事场次 |
| 镜头 | Shot | 场次内可独立制作和审核的视频单元 |
| 资产 | Asset | 角色、场景或道具图片资产 |
| 任务 | Task | 分配给一名制作人员的镜头视频或资产图片制作工作 |
| 版本 | Version | 一次正式提交、不可覆盖的制作产出物记录 |
| 审核意见 | Note | 绑定具体版本的文字、时间点或画面标注意见 |
| 审核动作 | Review Action | 通过、退回修改或稍后决定 |
| 审核单 | Review List | 按顺序组织待审核版本的业务对象 |
| 最终版 | Final Version | 经审核通过、作为任务最终结果的唯一版本 |

层级不变量：

- 一集必须且只能属于一个项目；
- 一个场次必须且只能属于一集；
- 一个镜头必须且只能属于一个场次；
- 一个资产必须且只能属于一个项目；
- 一个任务必须且只能属于一个镜头或一个资产制作分项；
- 一个版本必须且只能属于一个任务；
- 审核意见和审核动作必须绑定具体版本；
- 任何跨层级写操作都必须验证资源属于同一个项目。

## 4. 用户、角色与权限

### 4.1 身份来源

- 登录账号必须复用 RuoYi 平台用户，不另建业务账号体系。
- 平台管理员是全局授权能力，不作为 `sg_project_member` 中的项目角色。
- 项目总监和制作人员是项目内角色；同一用户在不同项目可以拥有不同角色和制作人缩写。

### 4.2 项目角色

| 代码 | 中文 | 业务职责 |
| --- | --- | --- |
| `director` | 项目总监 | 项目管理、成员管理、任务分配、审核和最终版确认 |
| `creator` | 制作人员 | 查看本人任务、开始任务、提交版本和处理审核意见 |

### 4.3 权限判断规则

访问项目资源必须同时满足：

```text
有效登录态
AND 平台接口权限
AND 项目成员身份或明确的全项目管理权限
AND 项目角色允许当前动作
AND 目标资源确实属于当前项目
```

前端按钮显隐只用于改善体验，不能替代后端鉴权。

### 4.4 角色权限矩阵

| 业务动作 | 平台管理员 | 项目总监 | 制作人员 |
| --- | --- | --- | --- |
| 创建项目 | 具备平台权限时允许 | 具备平台权限时允许 | 禁止 |
| 查看所属项目 | 允许 | 允许 | 允许 |
| 查看全部项目 | 需全项目管理权限 | 禁止 | 禁止 |
| 修改项目基本信息 | 允许 | 允许 | 禁止 |
| 归档项目 | 允许 | 允许 | 禁止 |
| 管理项目成员 | 允许 | 允许 | 禁止 |
| 管理集、场次、镜头、资产 | 允许 | 允许 | 默认禁止 |
| 导入镜头和资产表 | 允许 | 允许 | 禁止 |
| 分配或改派任务 | 允许 | 允许 | 禁止 |
| 查看所属项目任务、版本和审核意见 | 允许 | 允许 | 允许只读查看 |
| 开始任务 | 允许代操作并审计 | 允许代操作并审计 | 仅本人任务 |
| 提交版本 | 允许代提交并审计 | 允许代提交并审计 | 仅本人任务 |
| 提交审核意见 | 允许 | 允许 | 可查看与回复，不可作最终审核动作 |
| 通过/退回/稍后决定 | 允许 | 允许 | 禁止 |
| 确认最终版本 | 允许 | 允许 | 禁止 |

### 4.5 项目成员规则

- 创建项目时必须同时确定至少一名项目总监；创建人可以是首位项目总监。
- 一个项目始终至少保留一名活动项目总监，不得移除或降级最后一名活动项目总监。
- 项目成员采用可审计软移除；项目范围、成员列表、任务分配和 Excel 制作人匹配只认活动成员，历史任务仍保留原成员外键。
- 重新加入已移除用户时恢复原项目成员关系，不新建重复关系。
- 制作任务只能分配给当前项目中的活动成员。
- 可被分配任务的制作人员必须设置制作人缩写，例如 `YJF`。
- 制作人缩写只允许 2—12 位大写英文字母或数字，同一项目内唯一。
- 成员姓名变更不得改变已生成的历史文件名。
- 移除仍有未完成任务的成员前，必须先完成改派或显式取消处理，不能留下无负责人任务。

## 5. 项目需求

### 5.1 项目字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 项目名称 | 是 | 通常为中文，例如“罗刹夫人”；去除首尾空格，长度与非法字符限制由接口契约冻结 |
| 项目代号 | 是 | 2—12 位大写英文字母或数字，例如 `LCFR`；默认作为产出物文件名前缀 |
| 画幅 | 是 | 仅允许 `16:9`、`21:9`、`2.39:1`、`9:16`、`1:1` |
| 项目类型 | 是 | MVP 仅允许 `AI影视短片`，内部代码建议为 `ai_short_film`，必须保留可扩展字典设计 |
| 项目描述 | 否 | 项目背景、创作方向、交付目标等文本说明 |
| NAS 存储地址 | 是 | 从管理员配置并允许使用的 NAS 根目录中选择，创建前展示最终项目路径预览 |
| 项目总监 | 是 | 至少一名有效平台用户 |
| 项目成员 | 否 | 可在创建时添加，也可创建后维护 |
| 当前阶段 | 是 | 默认“筹备中”，用于项目概览展示 |

补充规则：

- MVP 中“项目代号”和“产出物文件名前缀”是同一个业务值，统一保存为 `project_code`，不再保留可与其漂移的第二个 `file_prefix` 业务字段。
- 项目代号在有效、未归档项目范围内大小写不敏感唯一。
- 项目名称可以重复，但同一 NAS 父目录下的项目物理路径不得冲突。
- 项目描述不得包含可执行 HTML；展示时必须按普通文本或经过安全净化的格式处理。

### 5.2 项目状态与阶段

项目生命周期状态：

| 代码 | 中文 | 说明 |
| --- | --- | --- |
| `preparing` | 筹备中 | 项目已创建，正在建立成员、集、镜头和资产 |
| `active` | 进行中 | 存在已分配或正在制作、审核的任务 |
| `completed` | 已完成 | 所有纳入交付的镜头和资产制作分项均完成 |
| `archived` | 已归档 | 项目只读保留，不再参与日常工作台统计 |

“当前阶段”是面向业务展示的独立字段，可以使用“筹备、资产制作、镜头制作、审核、交付”等字典值；不得通过修改阶段绕过任务和版本状态机。

### 5.3 创建项目流程

1. 用户填写并校验项目基本信息；
2. 用户选择 NAS 配置根目录，系统计算并展示最终项目目录；
3. 后端验证项目代号、成员、NAS 路径和写权限；
4. 后端检测同名目录、路径越界和并发创建冲突；
5. 创建项目记录及至少一名项目总监成员；
6. 在 NAS 上创建项目初始目录；
7. 记录目录初始化结果和审计日志；
8. 全部成功后才向用户显示“项目创建成功”。

数据库与 NAS 文件系统无法形成真正的单一事务，因此实现必须采用可恢复的补偿流程：

- 只能删除本次操作新建且确认为空的目录，不能清理任何预先存在目录；
- 数据库失败时应补偿本次新建目录；补偿失败时记录告警和待处理状态；
- NAS 创建失败时不得把项目显示为可正常使用；
- 重试必须幂等，不得重复创建成员、目录或项目记录。

### 5.4 修改与归档

- 修改项目名称不得自动移动或重命名已投入使用的 NAS 项目根目录。
- 项目创建时应保存不可变的 NAS 项目路径快照；路径迁移必须作为独立的管理员操作设计、审核和审计。
- 画幅、类型或项目代号一旦已有版本文件，默认禁止直接修改；确需修改必须明确对历史文件名和目录的影响。
- 项目归档不等于删除；归档后历史版本、审核意见、审核动作和 NAS 文件均保留。
- MVP 不提供从平台永久删除整个 NAS 项目目录的能力。

## 6. NAS 目录与存储规则

### 6.1 基本定义

NAS 地址是由后端服务器访问的 UNC 网络共享路径，例如：

```text
\\192.168.10.64\策划部
```

系统根据所选 NAS 根目录、项目类型目录名和项目路径名生成项目根目录：

```text
{NAS根目录}\{项目类型目录名}\{项目路径名}
```

示例：

```text
\\192.168.10.64\策划部\AI影视短片\罗刹夫人
```

浏览器不能被假定为能够直接访问或打开 UNC 路径。前端 MVP 必须提供“查看路径”和“复制路径”，只有部署环境已经安装并确认专用桌面协议处理器时，才可以增加“打开目录”。

### 6.2 NAS 配置边界

- 普通用户不能输入任意服务器路径，只能从管理员预先配置的 NAS 根目录中选择。
- 后端必须以服务账号访问 NAS；浏览器端不得获得 NAS 账号或密码。
- 后端必须对规范化后的最终路径进行允许根目录校验，防止 `..`、绝对路径替换、符号链接或重解析点逃逸。
- 日志不得记录 NAS 凭据；路径是否属于敏感信息由部署策略决定，接口只向有项目访问权的成员返回。
- 创建项目前必须验证根目录存在、可访问并具有所需创建/写入权限。

### 6.3 项目初始目录

创建项目时必须至少生成：

```text
{项目根目录}
├── ASSET
│   ├── Character
│   ├── Environment
│   └── Prop
└── VIDEO
```

完整路径示例：

```text
\\192.168.10.64\策划部\AI影视短片\罗刹夫人
\\192.168.10.64\策划部\AI影视短片\罗刹夫人\ASSET
\\192.168.10.64\策划部\AI影视短片\罗刹夫人\ASSET\Character
\\192.168.10.64\策划部\AI影视短片\罗刹夫人\ASSET\Environment
\\192.168.10.64\策划部\AI影视短片\罗刹夫人\ASSET\Prop
\\192.168.10.64\策划部\AI影视短片\罗刹夫人\VIDEO
```

### 6.4 动态目录

- 创建或导入新集时，在 `VIDEO` 下按集编号创建集目录。
- 创建或导入新镜头时，在对应集目录下创建镜头目录。
- 场次作为业务实体参与文件名和筛选，但按当前需求不单独创建物理目录。
- 推荐使用不随中文名称修改的稳定目录代码：集目录 `EP01`、`EP02`；镜头目录 `S001`、`S002`。
- 目录编号必须由后端基于正式业务编号生成，不能使用数据库主键或 Excel 行号。

```text
{项目根目录}\VIDEO
├── EP01
│   ├── S001
│   └── S002
└── EP02
    ├── S001
    └── S002
```

镜头版本目标路径示例：

```text
\\192.168.10.64\策划部\AI影视短片\罗刹夫人\VIDEO\EP01\S001\LCFR_EP001_001_S001_YJF_V001_1786094626499.mp4
```

### 6.5 资产目录

资产类型与目录映射固定为：

| 资产类型 | 中文 | 目录 |
| --- | --- | --- |
| `Character` | 角色 | `ASSET\Character` |
| `Environment` | 场景 | `ASSET\Environment` |
| `Prop` | 道具 | `ASSET\Prop` |

推荐每个资产建立独立子目录，以避免同类型资产版本混杂：

```text
ASSET\Character\张三三视图
ASSET\Environment\校园图
ASSET\Prop\灯
```

资产版本目标路径推荐为：

```text
{项目根目录}\ASSET\{资产类型}\{资产目录名}\{业务文件名}
```

原始示例同时出现了“直接存入类型目录”和“每资产独立子目录”两种方式，最终实现前必须完成第 21 节 D-03 决策。

### 6.6 目录名安全规则

- 用户可编辑名称不能原样作为路径片段，必须先执行 Windows/SMB 兼容校验。
- 禁止 `\ / : * ? " < > |`、控制字符、`.`、`..`、末尾空格和末尾句点。
- 禁止 Windows 保留名称，例如 `CON`、`PRN`、`AUX`、`NUL`、`COM1`、`LPT1` 等。
- 路径片段净化后为空、重名或超长时必须阻止创建，并提示用户修改名称，不能静默生成不可识别目录。
- 任何目录创建、文件写入、移动和清理都必须再次校验最终解析路径仍位于项目根目录内。

### 6.7 NAS 文件落位成功语义

制作人员看到“版本提交成功”时，必须同时满足：

1. 平台已收到并校验上传文件；
2. 文件已经以正式业务文件名安全写入目标 NAS 目录；
3. 文件摘要或等价完整性校验通过；
4. 版本、版本文件引用和自动审核单已经持久化；
5. 任务已经进入待审核状态。

如果其中任一步失败，不得生成对用户可见的半成品版本，也不得显示“提交成功”。实现可以采用临时文件、原子重命名、补偿任务和对账机制，但必须保证重试幂等，并保留可诊断记录。

## 7. 集与场次需求

### 7.1 集

每集至少包含：集编号、集名称/标题、描述、排序、状态和审计信息。

- 集编号在项目内唯一，例如 `01`、`02`；展示可格式化为 `EP01`。
- 集编号创建后原则上不修改；修改会影响 NAS 目录和镜头业务文件名，必须走受控迁移。
- 归档集前必须检查其下场次、镜头和未完成任务。

### 7.2 场次

每个场次至少包含：所属集、场次编号、场次名称、场次描述、排序、状态和审计信息。

- 场次编号在一集内唯一，例如 `001`、`002`。
- 场次用于镜头组织、筛选和业务文件名，不按当前基线创建独立 NAS 目录。
- 删除采用归档或逻辑删除，不能级联删除已有镜头、版本或审核记录。

## 8. 镜头管理需求

### 8.1 镜头字段

镜头列表正式字段为：

| 字段 | 说明 |
| --- | --- |
| 集 | 所属父级集 |
| 场次 | 所属父级场次 |
| 序号 | 集内成片顺序，不是数据库主键或 Excel 行号；导入时按 Sheet 内有效行顺序生成 |
| 镜头号 | 集内唯一镜头业务编号，跨场次连续使用 |
| 时长 | 统一按整数毫秒存储，页面可显示秒或时间码 |
| 制作人 | 从该镜头唯一任务聚合 |
| 镜头缩略图 | 从当前最新版本或最终版本的缩略图聚合 |
| 制作内容描述 | 对镜头画面和动作的制作要求 |
| 景别 | 例如远景、全景、中景、近景、特写 |
| 机位 | 相机高度、角度或位置说明 |
| 镜头运动 | 推、拉、摇、移、跟、升降等 |
| 焦段 | 以毫米为单位的数值或经确认的描述 |
| 场景 | 关联 `Environment` 资产，可多选 |
| 角色 | 关联 `Character` 资产，可多选 |
| 台词/对白 | 镜头内对白文本 |
| 音效 | 环境声、拟音或音效要求 |
| 色调参考 | 色彩、光线和氛围要求，可关联参考文件 |
| 备注 | 其他制作说明 |
| 当前最新反馈 | 从最新待处理版本的审核意见聚合，只读 |
| 状态 | 根据唯一任务和版本状态聚合，只读 |

道具通过镜头与 `Prop` 资产关系保存，可以作为可选列和详情字段展示。

### 8.2 查询与筛选

镜头页必须支持：

- 按集筛选；
- 按场次筛选；
- 按镜头号精确或模糊查询；
- 按聚合状态筛选；
- 按制作人筛选；
- 组合筛选、清空筛选和服务端分页；
- 保持表格、卡片和故事板三种视图使用同一查询结果与筛选条件。

### 8.3 三种视图

- 表格：适合批量浏览、筛选、排序和管理字段。
- 卡片：突出缩略图、镜头号、制作人、状态和最新反馈。
- 故事板：按成片序号展示镜头缩略图、时长和核心描述。

视图切换不得产生三套互相漂移的数据副本。

### 8.4 镜头增删改查

- 新建镜头必须指定所属集、场次、镜头号和成片序号。
- 指定制作人时自动创建唯一镜头视频任务；未指定时镜头状态为“未分配”。
- 修改镜头不得覆盖任务、版本和审核历史。
- 已产生版本后，影响业务文件名的集号、场次号、镜头号默认禁止直接修改。
- 删除采用归档或逻辑删除；存在未完成任务、版本或审核记录时不得物理删除。

### 8.5 导入台本/镜头表

当前正式镜头样表为 `.xlsx` 工作簿，每个可见 Sheet 代表一集。Sheet 名使用 `EP001`、`EP002` 等格式；导入行不再重复填写集号。每个 Sheet 的主数据区从 `A1` 开始，固定为以下 A:P 16 列：

```text
场次、镜头号、时长(s)、制作人、镜头缩略图、制作内容描述、景别、机位、
镜头运动、焦段(mm)、场景、台词/对白、音效、色调参考、备注、镜头状态
```

其中“镜头缩略图”和“镜头状态”为只读列，导入时忽略；集号从 Sheet 名派生；成片顺序从 Sheet 内有效行顺序派生。样表没有角色和道具列，当前导入不得从描述或备注中猜测这两类资产。

导入必须采用“上传文件—预检查—问题修正—确认提交”流程：

- 镜头模板版本为 `shot-v1`，资产模板版本为 `asset-v1`；默认单文件不超过 10 MiB、业务数据不超过 10000 行、预览有效期为 1800 秒；
- 预检查逐行返回成功、警告和错误；
- Sheet 名必须匹配 `EP` 加至少三位数字；规范化后的集号在工作簿内唯一；
- `序` 固定映射为场次号 `0`、场次代码 `000`、场次名称“序”；`01场` 等正片场次规范化为正整数和至少三位代码；
- 镜头号在整集内唯一，切换场次后不能重新从 `S001` 开始；
- 校验制作人存在、有效、属于项目且制作人缩写已设置；
- 场景名称已存在唯一 `Environment` 资产时直接建立关联；尚不存在时形成可追踪的待匹配资产需求，不在镜头导入中隐式创建正式资产；
- 焦段以文本保存，兼容 `135`、`35/25`、`24/18` 等样表值；
- 集数按有效 Sheet 派生的不同集号统计，场次数按不同“集号+场次号”统计，镜头数按不同“集号+镜头号”统计，不以 Excel 原始行数作为项目数量；
- 只解析从 A1 开始的首段连续表头；样表 Q:R 之后的辅助区域不得作为镜头数据读取；
- 正式提交前重新校验数据库状态，不能只相信预检查结果；
- 正式提交使用 `selectedRows[{sheetName,rowNumber}]` 唯一定位多 Sheet 行；选中行全事务提交，任一行失败则全部回滚；
- 重复提交同一导入凭据不得重复创建数据、任务、待匹配需求或目录操作。

## 9. 资产管理需求

### 9.1 资产类型

MVP 只允许：

- `Character`：角色；
- `Environment`：场景；
- `Prop`：道具。

项目类型和资产类型均应使用可扩展字典，但在未评审前不得接受其他值。

### 9.2 资产字段

| 字段 | 说明 |
| --- | --- |
| 类型 | Character、Environment 或 Prop |
| 名称 | 项目内可识别的资产名称 |
| 制作分项 | 资产下独立分配和审核的图片生产单元；允许暂缺，版本提交前必须补齐 |
| 资产描述 | 外观、功能、世界观或使用场景描述 |
| 任务描述 | 从当前制作分项唯一图片任务聚合或由分配时填写 |
| 备注 | 其他制作说明 |
| 状态 | 制作分项按唯一任务和版本聚合；资产按全部分项聚合，只读 |
| 制作人 | 从当前制作分项唯一任务聚合，只读；每个分项仅一名主制作人 |

资产缩略图、最新版本和使用镜头数可以作为附加只读信息展示。

### 9.3 导入资产表

创建项目并成功导入镜头表后，项目总监可以导入资产 Excel。当前正式样表为 `docs/资产-样表.xlsx`，主数据区是 `Sheet1!A:G`：类型、名称、描述、制作分项、备注、状态、制作人。合并单元格表示资产父级，每个有效明细行表示一个制作分项。

资产导入同样采用“上传文件—预检查—问题修正—确认提交”流程：

- 类型只允许 `Character`、`Environment`、`Prop` 或对应中文别名；
- 预检查按资产类型分别显示有效资产数、重复数和错误数；
- 同一项目、同一类型的规范化资产名称必须唯一；
- 制作分项允许为空，预检查只返回警告并允许正式导入，后续可以编辑补充；提交图片版本前必须存在有效制作分项；
- 每个制作分项只允许一名主制作人，`蒋浩/春霞` 等复合制作人值必须返回行错误；
- MVP 只新增资产或制作分项；已有同类型同名称资产可作为父级复用，但资产字段不得被 Excel 静默覆盖，冲突必须报错；
- 制作人必须存在、有效、属于项目且制作人缩写已设置；
- 合并单元格只在明确合并范围内继承左上角值；预检查行规范化后是自包含记录，允许选中同一父资产下的部分可导入分项；
- 正式提交后按“项目+资产类型+规范化名称”自动匹配镜头导入产生的待匹配需求；
- 只有唯一候选允许自动关联，无法匹配或存在冲突时进入人工处理列表；
- 任一选中行失败时全部回滚，重复幂等请求不得重复创建资产、任务、关系或目录操作。

“根据资产表决定有多少类型”表示统计本次文件实际包含三种允许类型中的哪些类型及其数量，不表示导入文件可以自行创建新的资产类型代码。

### 9.4 镜头资产待匹配规则

- 待匹配需求保存 Excel 原始名称、规范化名称、资产类型、来源镜头和导入批次；
- 状态至少包含待匹配、已匹配、冲突和已忽略；
- 自动匹配成功后建立正式镜头资产关系，不删除来源审计信息；
- 人工选择资产或忽略需求必须记录操作者、时间和原因；
- 资产改名后不得静默重写历史原始名称，应执行受控重新匹配；
- 项目概览应分别展示总资产数与未解决的待匹配/冲突数量。

### 9.5 资产规则

- 资产名称在同一项目、同一资产类型内应唯一。
- 一个资产可以有多个制作分项；每个制作分项首次分配主制作人时创建唯一资产图片任务，改派更新原任务。
- 资产可以关联多个镜头，镜头也可以关联多个资产。
- 制作分项未产生版本时允许补充或纠正；已有版本后不得普通修改，也不得自动改写历史业务文件名。
- 资产归档前必须提示其被哪些镜头使用；不得级联删除镜头关系之外的历史版本和审核记录。

## 10. 任务管理需求

### 10.1 任务类型与唯一性

| 任务类型 | 归属 | 产出物 |
| --- | --- | --- |
| `shot_video` | 一个镜头 | MP4 或 MOV 视频 |
| `asset_image` | 一个资产制作分项 | JPG 或 PNG 图片 |

- 一个镜头最多有一个正式 `shot_video` 任务。
- 一个资产制作分项最多有一个正式 `asset_image` 任务。
- 一个任务不能同时属于镜头和资产制作分项，也不能成为无归属任务。
- 首次分配制作人时创建任务；后续改派更新同一任务并记录审计。
- 已完成任务默认禁止直接改派或覆盖；返工必须设计显式“重新打开任务”动作。

### 10.2 任务字段

任务至少包含：任务类型、所属项目、所属镜头或资产、负责人、任务描述、优先级、截止日期、状态、最新版本、最终版本和审计信息。

### 10.3 任务状态流转

```text
未开始 not_started
  └── 开始任务 ──→ 制作中 in_progress

制作中 in_progress
  └── 上传并提交版本 ──→ 待审核 pending_review

待审核 pending_review
  ├── 确认通过 ──→ 已完成 completed
  ├── 退回修改 ──→ 修改中 revision
  └── 稍后决定 ──→ 待审核 pending_review

修改中 revision
  └── 上传并提交新版本 ──→ 待审核 pending_review
```

不允许普通用户任意修改状态代码。每次状态变化必须由明确业务动作触发并记录操作人、时间和原因。

### 10.4 我的任务

制作人员必须能够查看：

- 分配给自己的未开始、制作中、待审核和修改中任务；
- 任务所属项目、镜头或资产、制作要求、截止日期和优先级；
- 历史版本、当前审核意见和下一步动作；
- 由退回意见产生的待修改事项。

## 11. 版本与文件命名规则

### 11.1 版本通用规则

- 每次正式提交必须创建一个新版本，版本从 `V001` 开始在任务范围内连续递增。
- 版本号由后端在并发安全的事务中分配，前端不能根据列表长度计算。
- 已提交版本不可覆盖、替换或删除；修订必须提交新版本。
- 版本必须记录提交人、提交时间、修改说明、主产出物和文件摘要。
- 同一任务同时只能存在一个最终版本。
- 时间戳必须由服务器生成，为 Unix 毫秒时间戳。

### 11.2 镜头视频文件名

规范：

```text
{项目代号}_EP{集号至少3位}_{场次号至少3位}_S{镜头号至少3位}_{制作人缩写}_V{版本号至少3位}_{服务端毫秒时间戳}.{mp4|mov}
```

示例：

```text
WGZR_EP001_001_S001_YJF_V001_1786094626499.mp4
```

“序”中的镜头使用场次代码 `000`，例如：

```text
WGZR_EP001_000_S001_YJF_V001_1786094626499.mp4
```

字段含义：

- `WGZR`：项目代号；
- `EP001`：第一集；
- `001`：第一场；
- `S001`：第一个镜头；
- `YJF`：制作人缩写；
- `V001`：任务的第一个正式版本；
- `1786094626499`：服务端 Unix 毫秒时间戳。

镜头业务文件名包含 `V001/V002`，并且必须与后端任务范围内连续生成的正式版本号、审核单和页面展示一致。

### 11.3 资产图片文件名

规范：

```text
{项目代号}_Asset_{Character|Environment|Prop}_{安全资产名称}_{安全制作分项}_{制作人缩写}_V{版本号至少3位}_{服务端毫秒时间戳}.{jpg|png}
```

示例：

```text
WGZR_Asset_Environment_动力舱室内_动力舱恐怖气氛主视角_YJF_V001_1786094626499.jpg
```

### 11.4 命名约束

- 项目代号、制作人缩写、版本号和时间戳均使用提交时已确认的服务端值；镜头和资产文件名都包含服务端版本号。
- 文件扩展名统一转为小写，并与实际媒体类型一致。
- 资产名称和制作分项进入文件名之前必须按路径安全规则校验，但不得静默替换成无法追溯的名称。
- 相同版本不得因重复请求生成两个时间戳或两个业务文件名。
- 历史文件名在项目、成员或资产改名后保持不变。
- 平台内部物理存储名与业务文件名是两个概念；页面和 NAS 使用业务文件名，平台文件基座仍保留稳定 `fileId`、摘要和业务引用。

### 11.5 文件校验

- 镜头任务只接受 MP4、MOV；资产任务只接受 JPG、PNG。
- 后端必须同时校验扩展名、声明的 MIME 类型和实际文件内容，不能只信任浏览器上传值。
- 文件大小上限、视频编码、图片分辨率和视频时长限制属于部署参数，必须在实施前冻结并在前端提前提示。
- 失败上传、未被版本引用的临时文件必须纳入保留、回收和对账机制。

## 12. 审核单、审核意见与审核动作

### 12.1 自动审核单

- 每次版本提交成功，必须自动创建一个只包含当前版本的审核单。
- 版本创建、文件引用、自动审核单创建和任务进入待审核必须形成一个一致的业务结果。
- 退回后重新提交新版本，必须生成新的审核单；旧版本、旧意见和旧审核单不得覆盖。

### 12.2 人工批量审核单

项目总监或管理员可以将同一项目的多个待审核版本加入人工批量审核单，并按明确顺序连续审核。人工批量审核单不改变版本原本所属的自动审核单和任务。

### 12.3 审核意见

- 每条意见必须绑定具体版本和创建人。
- 视频意见可以绑定整数毫秒时间点。
- 图片或视频画面标注使用 `0..1` 归一化坐标，并记录标注类型、颜色、点集和创建时媒体尺寸。
- 意见可以区分普通评论和必须修改项。
- 切换版本后，未提交草稿不能错误提交到旧版本。
- 已提交意见不得被普通用户覆盖；修改应保留修订审计或通过新回复补充。

### 12.4 审核动作

| 动作 | 代码 | 前置条件 | 结果 |
| --- | --- | --- | --- |
| 确认通过 | `approve` | 版本待审核，操作者有审核权限 | 当前版本成为最终版，任务完成 |
| 退回修改 | `reject` | 版本待审核，必须提供退回原因或至少一条必须修改意见 | 版本已退回，任务进入修改中 |
| 稍后决定 | `defer` | 版本待审核 | 仅记录动作，版本和任务保持待审核 |

审核动作必须是不可变历史。并发审核时，后到请求必须得到明确冲突提示，不能产生两个最终版本或将已完成任务重新改为修改中。

### 12.5 审核循环

```text
分配任务
→ 制作人员在线下制作
→ 上传并提交 V001
→ 自动创建 V001 审核单
→ 项目总监审核
   ├── 通过：V001 为最终版，任务完成
   ├── 稍后决定：继续待审核
   └── 退回：任务进入修改中
       → 制作人员线下修改
       → 上传并提交 V002
       → 自动创建 V002 审核单
       → 再次审核，直至某一版本通过
```

## 13. 项目概览与统计口径

### 13.1 概览字段

项目概览至少展示：

- 项目当前阶段；
- 总集数；
- 总场次数；
- 总镜头数；
- 总资产数；
- 总制作分项数；
- 镜头完成数；
- 资产完成数；
- 制作分项完成数；
- 待审核镜头数；
- 待审核资产数；
- 待审核制作分项数；
- 正在修改中的镜头数；
- 正在修改中的资产数；
- 正在修改中的制作分项数；
- 未分配镜头数；
- 未分配资产数；
- 未分配制作分项数；
- 整体完成度。

### 13.2 统计规则

| 指标 | 计算口径 |
| --- | --- |
| 总集数 | 当前项目中未逻辑删除、未归档的集数量 |
| 总场次数 | 当前项目中未逻辑删除、未归档的场次数量 |
| 总镜头数 | 当前项目中未逻辑删除、未归档的镜头数量 |
| 总资产数 | 当前项目中未逻辑删除、未归档的资产数量 |
| 镜头完成数 | 聚合状态为 `completed` 且存在最终版本的镜头数量 |
| 总制作分项数 | 当前项目中未逻辑删除、未归档的资产制作分项数量 |
| 资产完成数 | 至少有一个活动制作分项，且所有活动制作分项均已完成并存在最终版本的资产数量 |
| 制作分项完成数 | 唯一任务为 `completed` 且存在最终版本的制作分项数量 |
| 待审核镜头数 | 唯一任务状态为 `pending_review` 的镜头数量 |
| 待审核资产数 | 至少一个制作分项任务为 `pending_review` 的资产数量 |
| 待审核制作分项数 | 唯一任务状态为 `pending_review` 的制作分项数量 |
| 修改中镜头数 | 唯一任务状态为 `revision` 的镜头数量 |
| 修改中资产数 | 至少一个制作分项任务为 `revision` 的资产数量 |
| 修改中制作分项数 | 唯一任务状态为 `revision` 的制作分项数量 |
| 未分配镜头数 | 尚未创建唯一任务的镜头数量 |
| 未分配资产数 | 至少一个活动制作分项尚未创建任务的资产数量 |
| 未分配制作分项数 | 尚未创建唯一任务的资产制作分项数量 |

整体完成度默认采用等对象权重：

```text
整体完成度 = (镜头完成数 + 制作分项完成数) ÷ (总镜头数 + 总制作分项数) × 100%
```

- 分母为 0 时显示 `0%`，不得显示 `NaN` 或 `100%`。
- 结果保留一位小数或按统一界面规则取整。
- 所有统计必须来自后端统一聚合口径，不能由前端对当前分页数据自行累加。
- 已归档、逻辑删除或不纳入交付的对象是否计入统计必须由明确字段决定。

### 13.3 镜头、制作分项和资产聚合状态

| 代码 | 中文 | 计算条件 |
| --- | --- | --- |
| `unassigned` | 未分配 | 尚无正式任务 |
| `not_started` | 未开始 | 唯一任务为未开始 |
| `in_progress` | 制作中 | 唯一任务为制作中 |
| `reviewing` | 审核中 | 唯一任务为待审核 |
| `revision` | 修改中 | 唯一任务为修改中 |
| `completed` | 已完成 | 唯一任务已完成且存在最终版本 |

普通成员不能手动设置聚合状态。

上表直接用于镜头和制作分项。资产包含多个活动制作分项时，全部分项完成且均存在最终版本才聚合为 `completed`；否则按 `revision`、`reviewing`、`in_progress`、`unassigned`、`not_started` 的优先顺序返回需要处理的状态。

必须审计：

## 16. 数据一致性与并发规则

- 项目代号、项目内制作人缩写、集号、场次号、镜头号和资产名称必须有明确唯一约束。
- 一个镜头或资产制作分项最多一个正式任务，必须由数据库约束和服务层共同保证。
- 版本号分配、最终版本唯一性和审核动作必须具备并发保护。
- 前端写操作必须防重复提交；关键业务动作使用幂等键或等价机制。
- 资源更新应使用乐观锁或等价并发控制，过期页面不能静默覆盖他人修改。
- 创建版本、版本文件关系、平台文件业务引用、自动审核单和任务状态必须形成一致业务事务。
- NAS 与数据库跨资源操作必须有可重试、补偿和对账机制。
- 已提交版本、审核意见、审核动作和最终文件不能被普通 CRUD 覆盖。

## 17. 文件访问与安全规则

- 版本文件必须保留平台稳定 `fileId`，并同步业务引用，防止仍被版本使用时误删。
- NAS 路径访问权与平台文件下载权必须分别校验；项目成员身份不能自动等同于平台文件 ACL。
- 平台权限不能阻止用户绕过网页直接访问 SMB/UNC 共享。部署时必须通过 NAS、Windows/AD 或等价机制配置共享权限；如果整个部门共享对所有项目开放，系统必须明确接受“平台外可直接访问文件”的安全边界。
- 私有文件默认拒绝访问；只有拥有项目资源权限并通过文件授权的用户才能预览或下载。
- 项目成员可以只读查看所属项目的镜头、资产、任务、版本、意见和经授权文件；制作人员只能开始、提交或重试分配给自己的任务。
- 文件接口不得向前端泄露平台内部 `storage_key`、服务器本地路径或访问凭据。
- 下载文件名使用不可变业务文件名，并防止响应头注入。
- 永久删除文件或目录不属于普通项目操作；如未来实现，必须精确确认目标、权限、业务引用和恢复策略。
- NAS 对账至少应检查数据库引用、目标路径存在性、文件大小和 SHA-256 或等价摘要。

## 18. 非功能要求

### 18.1 可用性

- 桌面端为第一优先级，常用操作不得只在鼠标悬停时出现。
- 表单字段必须有明确标签、校验提示和错误定位。
- 搜索筛选条件应可清空；长列表采用服务端分页或虚拟化。
- 上传大文件必须展示真实进度、失败原因和可控重试，不得使用虚假进度。

### 18.2 性能

- 项目概览使用后端聚合或缓存，不得拉取全量镜头和资产到前端计算。
- 镜头、资产、任务、版本和审核列表必须分页。
- 图片缩略图和视频代理如未实现，不得直接用原始大文件伪装为已优化媒体。
- 文件大小上限、分页默认值和目标响应时间由部署环境压测后冻结。

### 18.3 可恢复性

- NAS 暂时不可用时必须失败关闭文件写入，并给出可诊断错误。
- 重试不能重复生成版本、审核单或业务文件。
- 数据库与 NAS 对账异常应进入管理员待处理清单。
- 备份恢复必须同时考虑 PostgreSQL、平台文件存储、NAS 项目目录和配置密钥。

### 18.4 可扩展性

- 项目类型使用代码与显示名称分离的字典设计，MVP 只启用 `AI影视短片`。
- 画幅使用受控枚举，新增画幅必须通过配置或版本化变更。
- 后续增加资产类型、外部审核、自动媒体处理或桌面客户端时，不得破坏现有版本不可变和审核绑定规则。

## 19. 核心验收场景

### 19.1 项目与 NAS

- 能以“罗刹夫人 / LCFR / 16:9 / AI影视短片”创建项目并指定至少一名项目总监。
- 创建成功后，NAS 项目根目录及 `ASSET/Character`、`ASSET/Environment`、`ASSET/Prop`、`VIDEO` 均真实存在。
- NAS 不可访问、不可写、路径越界或目标冲突时，项目不会被显示为创建成功。
- 重复提交创建请求不会产生重复项目、成员或目录。
- 修改项目名称不会静默移动已存在的 NAS 根目录。

### 19.2 镜头闭环

- 项目总监创建集、场次和镜头，将镜头分配给项目制作人员。
- 系统只创建一个 `shot_video` 任务，并在 NAS 创建对应集和镜头目录。
- 制作人员开始任务并上传合法视频，系统生成 `V001`、规范业务文件名和自动审核单。
- 项目总监退回并填写意见，任务进入修改中；制作人员再次上传生成 `V002`，`V001` 仍可追溯。
- 项目总监通过 `V002` 后，仅 `V002` 为最终版，任务和镜头均为已完成。

### 19.3 资产闭环

- 项目总监创建 Character、Environment 或 Prop 资产及一个或多个制作分项，并为每个分项分配一名主制作人。
- 系统为每个制作分项只创建一个 `asset_image` 任务；缺少制作分项名称时可保存和分配，但提交版本前必须补齐。
- 制作人员上传合法图片后生成规范业务文件名、版本和自动审核单。
- 经多轮退回和提交后，每个制作分项只有一个最终版本；全部活动分项完成后资产聚合状态为已完成。

### 19.4 权限与负向场景

- 非项目成员即使知道资源 ID，也不能读取项目数据或文件。
- 制作人员不能给自己分配其他任务、管理成员或执行最终审核。
- 制作人员不能给非本人任务提交版本。
- 镜头任务上传图片、资产任务上传视频必须被拒绝。
- 并发提交版本不会生成相同版本号；并发审核不会产生两个最终版本。
- 已提交版本文件、审核意见和审核动作不能被普通编辑接口覆盖。
- NAS 发布失败、数据库提交失败或网络中断后，系统不存在对用户可见的虚假成功版本。

### 19.5 项目概览

- 统计值与数据库内未归档镜头、资产、制作分项及其唯一任务状态一致。
- 待审核、修改中、完成数和整体完成度使用统一后端口径。
- 分页、筛选和视图切换不会改变项目总统计结果。

## 20. MVP 完成定义

只有同时满足以下条件，才能将 MVP 描述为完成：

1. 项目、成员、集、场次、镜头和资产可以在真实 PostgreSQL 中持久化；
2. 项目创建可在真实测试 NAS 或受控 SMB 测试共享上完成目录初始化；
3. 镜头和资产制作分项均完成“分配—制作—上传—版本—审核—退回—再提交—通过”闭环；
4. 业务文件真实落位且可由有权限的成员访问，命名和目录符合规则；
5. 权限、并发、重复提交、NAS 故障和非法文件等负向场景已验证；
6. 项目概览统计与真实数据一致；
7. 已执行后端、前端和真实浏览器 E2E 验收，并记录实际命令和结果。

源码存在、页面可打开、Mock 演示、静态检查通过、构建成功、服务启动成功或健康检查成功，都不能单独替代上述业务闭环验收。

## 21. 待确认事项与当前冲突

以下事项不影响本文形成需求基线，但会影响实现，必须在编码前完成业务确认：

| 编号 | 待确认事项 | 当前建议 |
| --- | --- | --- |
| D-01 | 用户在创建项目时选择的是 NAS 根目录，还是已包含项目类型和项目名称的完整目录 | 选择管理员配置的 NAS 根目录，由系统计算并预览完整项目目录 |
| D-02 | 集、镜头物理目录是否包含中文名称，如 `EP01 第一集`、`S001 镜头1` | 使用稳定代码 `EP01`、`S001`；中文名称只在页面显示，避免改名导致目录迁移 |
| D-03 | 资产文件直接存入类型目录，还是每个资产建立独立子目录 | 每个资产建立独立子目录，避免同类型资产的多版本混杂 |
| D-04 | 原始说明中的“项目资料、声音、成片交付、交换目录”是否属于本期必建目录 | 当前确认树只包含 `ASSET` 和 `VIDEO`；如需 `DOC/AUDIO/DELIVERY/EXCHANGE`，应补充用途和写入规则后纳入 |
| D-05 | 最大图片/视频大小、允许的视频编码、分辨率和时长限制 | 根据局域网带宽、NAS 容量和浏览器播放能力压测后冻结 |
| D-06 | NAS 文件落位采用同步提交还是后台发布 | 对用户的成功语义保持一致；大视频建议后台发布，但版本在发布完成前不可进入待审核 |
| D-07 | 资产在镜头表导入时不存在，系统应自动创建还是报错 | 已确认采用镜头先导、资产后导：不自动创建正式资产，先保存待匹配需求；资产导入后唯一匹配，冲突人工处理 |
| D-08 | 项目总体完成度是否需要区分镜头和资产权重 | MVP 使用等对象权重；有明确制片管理要求后再引入可配置权重 |
| D-09 | 项目总监能否修改已完成任务并重新打开 | 默认禁止；如业务需要，新增有原因、有审计的“重新打开”动作 |
| D-10 | 浏览器是否具备公司统一的 UNC 桌面协议处理器 | 未确认前只提供查看和复制路径，不提供直接打开按钮 |
| D-11 | Shot Grid 直接放入若依管理端还是建设独立业务端 | 已确认采用独立 `shot-grid-frontend`；共用若依后端、账号、权限、字典和文件能力，系统管理仍留在 `ruoyi-fastapi-frontend` |
| D-12 | 镜头视频业务文件名是否包含版本号 | 已确认包含；使用“项目代号_EP集_场次_S镜头_制作人_V版本_服务端时间戳”，并与内部版本及审核历史一致 |
| D-13 | 样表中的“序”如何映射为场次 | 已确认使用 `scene_no=0`、场次代码 `000`、场次名称“序”；对应业务文件名场次段为 `000` |
| D-14 | 资产图片业务文件名是否包含制作分项 | 已确认包含；位于资产名称与制作人缩写之间，使用保存并安全规范化后的制作分项 |
| D-15 | 制作分项缺失和负责人规则 | 已确认：缺失制作分项不报错，可导入后编辑补充，但提交版本前必须补齐；每个制作分项只允许一名主制作人 |

## 22. 领域/API 契约同步结果

《领域模型与 API 契约》v1.0 仍是完整目标设计；截至 2026-08-10，其中项目创建/列表/详情/概览/存储状态、成员管理、范围导航和镜头/资产 Excel 预检与提交已有后端实现；其余仍为计划接口。准确边界、字段和错误见《[第一批后端联调清单](./第一批后端联调清单.md)》；该结论是静态核对和契约测试，不是联调/E2E 结论。

| 需求差异 | v1.0 设计结论 |
| --- | --- |
| 项目描述 | `sg_project.project_description` |
| 项目代号与文件前缀 | 统一使用 `project_code`，不再保留可漂移的第二业务值 |
| NAS 根目录与项目路径 | 新增 `sg_storage_root`、`sg_project_storage` 和不可变路径快照 |
| NAS 动态目录 | 新增 `sg_storage_operation` Outbox、租约、幂等重试和安全补偿 |
| 版本文件落位 | 新增 `sg_version_submission`，先发布 NAS，再短事务创建正式版本和审核单 |

## 版本审核具名动作（已实现契约）

版本审核使用任务归属路径下的 `POST .../versions/{versionId}/approve|reject|defer`，请求携带版本 `lockVersion`；退回必须携带非空 `reason`。接口同时校验平台权限、活动项目成员、`director` 项目角色、项目/任务/版本归属及待审核状态。重复动作、过期乐观锁、已完成任务和并发最终版本冲突返回 HTTP 409 与稳定 `errorKey`。

`approve` 在同一事务及行锁内保证当前版本是任务唯一 `final` 并将任务置为 `completed`；`reject` 将当前版本置为 `rejected`、任务置为 `revision`，审核意见写入不可变动作历史；`defer` 保持版本和任务待审核语义，只记录不可变动作并推进乐观锁。普通更新接口不得直接写 `version_status` 或审核相关 `task_status`。退回后的下一次正式提交创建新版本，旧版本、自动审核单、意见、回复和审核动作均不可变。

## 人工批量审核单（已实现基线）

人工审核单由有项目总监权限的成员创建，只能选择当前项目且仍处于可审核业务状态的版本。跨项目版本、重复版本、重复顺序以及选择后发生状态变化均拒绝写入。排序以关系表中的明确顺序为准，并受审核单乐观锁保护。自动单版本审核单不是前端可创建资源，仍与版本正式提交保持同一事务。
