# AI影视项目管理工具

## ShotGrid轻量化设计方案

# 一、核心设计

整套系统只需要围绕一句话设计：

项目里有镜头和资产，镜头与资产下面有任务，每次提交形成一个版本，负责人对版本进行审核。

系统核心关系：

项目 Project
├─ 场次 Scene
│  └─ 镜头 Shot
│    ├─ 任务 Task
│    ├─ 版本 Version
│    └─ 审核意见 Note
│
├─ 资产 Asset
│  ├─ 角色 Character
│  ├─ 场景 Environment
│  └─ 道具 Prop
│    ├─ 任务 Task
│    ├─ 版本 Version
│    └─ 审核意见 Note
│
└─ 审核单 Review List
  └─ 多个待审核版本

不再单独建立大量复杂模块。



------



# 二、保留ShotGrid的五个核心概念

## 1. 实体 Entity

ShotGrid使用实体表示项目中被管理的对象，例如Asset、Sequence和Shot。

轻量版只保留五种实体：

· 项目

· 场次

· 镜头

· 资产

· 用户

其中资产只分为：

· 角色

· 场景

· 道具

· 其他

车辆、生物、服装、武器、灯光色表等内容，通过资产类型标签区分，不再创建新的数据模块。



------



## 2. 任务 Task

ShotGrid的Task挂在Shot或Asset等对象下面，用于记录负责人、制作环节、开始时间和截止时间。

轻量版任务字段只保留：

· 任务名称

· 所属镜头或资产

· 制作环节

· 负责人

· 状态

· 优先级

· 截止日期

· 制作要求

· 前置任务

· 最新版本

不需要复杂工时、预算、成本代码、排期模型等功能。



------



## 3. 版本 Version

在ShotGrid中，Version表示一次提交审核的工作迭代，可以关联镜头、资产或其他实体。

例如：

SH010 AI视频生成
├─ V001 首次测试
├─ V002 修改人物动作
├─ V003 修改镜头运动
└─ V004 审核通过

每个版本记录：

· 版本号

· 文件

· 缩略图

· 提交人

· 提交时间

· 修改说明

· 审核状态

· 提示词与生成参数

· 原始文件路径

旧版本不能被覆盖。



------



## 4. 审核意见 Note

审核意见必须绑定具体版本。

例如：

镜头：SH010
版本：V003
时间点：00:02.12
意见：人物转头速度太快，需要减慢约30%
状态：待修改

审核意见字段：

· 审核人

· 文字意见

· 视频时间点

· 图片或视频标注

· 是否必须修改

· 处理状态

· 制作人员回复



------



## 5. 审核单 Review List

对应ShotGrid中的Playlist。

ShotGrid的Playlist本质上是一个按顺序排列的Version列表，可用于组织审核、提交审片或共享一批版本。

轻量版改名为：

## 审核单

例如：

7月28日视频审核
├─ SH001 V003
├─ SH005 V006
├─ SH012 V002
└─ SH016 V004

项目总监打开一个审核单，就可以连续观看所有待审核内容。



------



# 三、系统只保留六个页面

## 1. 我的工作台

每个人登录后首先看到：

· 我的制作任务

· 我的待修改任务

· 待我审核

· 今日截止

· 被阻塞任务

· 最近提交

制作人员不需要进入复杂的项目后台。

点击任务即可看到全部制作资料。



------



## 2. 项目页面

项目页面只显示：

项目概况
剧本与场次
镜头
资产
审核
成员

顶部显示：

· 项目名称

· 当前阶段

· 总镜头数

· 已完成镜头数

· 待审核镜头

· 修改中镜头

· 阻塞镜头

· 交付日期



------



## 3. 镜头页面

这是整个系统最重要的页面。

采用类似ShotGrid的表格管理方式，但字段明显减少。

| 镜头  | 缩略图 | 场次 | 时长 | 当前环节 | 负责人 | 状态   | 最新版本 |
| ----- | ------ | ---- | ---- | -------- | ------ | ------ | -------- |
| SH001 | 图片   | SC01 | 5秒  | 视频生成 | 张三   | 制作中 | V003     |
| SH002 | 图片   | SC01 | 4秒  | 总监审核 | 李四   | 待审核 | V006     |
| SH003 | 图片   | SC02 | 7秒  | 剪辑     | 王五   | 修改中 | V004     |

支持三种显示方式：

### 表格模式

适合总监、制片和部门负责人。

### 卡片模式

适合美术、视频生成和审核。

### 故事板模式

按照成片顺序显示镜头缩略图和时长。

第一版不需要复杂甘特图。



------



## 4. 资产页面

统一管理：

· 角色

· 场景

· 道具

· 服装

· 载具

· 生物

· 风格参考

资产表格：

| 资产      | 类型 | 缩略图 | 负责人 | 状态   | 最新版本 | 使用镜头 |
| --------- | ---- | ------ | ------ | ------ | -------- | -------- |
| 苟翱天    | 角色 | 图片   | 张三   | 已定稿 | V008     | 42       |
| NoMud舱室 | 场景 | 图片   | 李四   | 修改中 | V012     | 18       |
| 尖叫鸡    | 道具 | 图片   | 王五   | 已定稿 | V003     | 4        |

点击资产后显示：

· 资产说明

· 当前批准版本

· 历史版本

· 相关任务

· 审核意见

· 使用该资产的镜头

· 参考图片

· 提示词



------



## 5. 审核页面

审核页面参考ShotGrid Review，但进一步简化。

左侧：

· 待审核版本列表

中间：

· 图片或视频播放器

· 前后版本切换

· A/B对比

右侧：

· 审核意见

· 历史意见

· 当前任务信息

底部只保留四个按钮：

通过
退回修改
稍后决定
设为最终版本

审核意见可以：

· 点击视频时间点记录

· 在画面上画圈

· 添加箭头

· 输入文字

· 上传参考图片



------



## 6. 文件页面

文件页面不做成复杂的数字资产管理系统。

只负责：

· 查看项目文件

· 搜索文件

· 查看文件版本

· 下载原文件

· 打开NAS路径

· 查看文件所属镜头或资产

文件必须挂在某个对象下面：

文件
→ 属于某个版本
→ 版本属于某个任务
→ 任务属于某个镜头或资产

尽量避免出现没有归属的文件。

# 四、两条生产管线

不需要给每个部门建立单独系统，只建立两条Pipeline。

# 管线一：镜头制作

台本
↓
视觉准备
↓
视频生成
↓
剪辑
↓
声音
↓
成片

## 镜头任务模板

每创建一个镜头，可以自动生成以下任务：

| 环节     | 主要负责内容                     |
| -------- | -------------------------------- |
| 台本     | 镜头描述、景别、运镜、表演和台词 |
| 视觉准备 | 首帧、尾帧、角色、场景和道具准备 |
| 视频生成 | AI视频生成、筛选和修复           |
| 剪辑     | 镜头使用、节奏和镜头替换         |
| 声音     | 对白、环境声、音效和音乐         |
| 成片     | 最终检查和输出                   |

项目总监不是单独的制作环节，而是各阶段的审核人。



------



# 管线二：美术资产制作

需求
↓
概念设计
↓
修改
↓
定稿

角色、场景和道具都使用同一个任务模板。

例如角色：

角色需求
→ 概念设计
→ 三视图或定妆图
→ 总监审核
→ 资产定稿

例如场景：

场景需求
→ 氛围概念
→ 关键角度
→ 总监审核
→ 资产定稿

不需要分别开发角色系统、场景系统和道具系统。

# 五、状态设计

ShotGrid可以为不同实体配置大量状态，但轻量版应严格限制状态数量。ShotGrid本身也允许按项目隐藏不需要的实体、字段、步骤和状态。

## 任务状态

只保留六种：

未开始
制作中
待审核
修改中
已完成
已阻塞

## 版本状态

只保留四种：

待审核
已通过
已退回
最终版

## 镜头和资产状态

系统根据任务自动计算：

未开始
制作中
审核中
已完成
已锁定

成员不需要手动修改镜头总状态。

# 七、AI影视特有字段

传统ShotGrid主要管理制作任务和媒体版本。

你们的系统应在Version下面增加AI生成信息。

## 图片版本字段

· 使用模型

· 模型版本

· 提示词

· 参考图

· Seed

· 分辨率

· 画面比例

· 生成平台

· 生成费用

· 是否经过后期处理

## 视频版本字段

· 使用模型

· 模型版本

· 完整提示词

· 首帧

· 尾帧

· 参考视频

· 时长

· 分辨率

· 画幅

· Seed

· 运镜模式

· 生成费用

· 原始生成文件

· 修复后文件

这些字段默认折叠。

普通审核人员只看到画面和修改说明；需要复现时再展开生成参数。

# 八、文件管理简化方式

不复制ShotGrid复杂的Published File体系。

系统内部只区分两种文件：

## 1. 审核文件

用于网页播放和审核：

· JPG

· PNG

· MP4

· WAV

· MP3

上传后自动生成缩略图和代理文件。

## 2. 源文件

用于实际制作：

· PSD

· EXR

· PR工程

· 达芬奇工程

· AE工程

· Nuke工程

· 无压缩视频

· 图片序列

源文件可以：

· 上传云存储

· 保存NAS路径

· 保存本地同步路径

例如：

网页审核文件：
SH010_VIDEO_V004_review.mp4

NAS源文件：
\\NAS\NOMUD\EP01\SC03\SH010\video\v004\

不需要第一版就开发完整的自动发布工具。

# 十、标准使用流程

## 第一步：创建项目

填写：

· 项目名称

· 项目类型

· 画幅

· 总时长

· 交付日期

· 项目总监

· 项目成员

## 第二步：导入台本

通过Excel或表格导入：

· 场次

· 镜头编号

· 镜头描述

· 时长

· 角色

· 场景

· 道具

· 台词

系统自动创建场次和镜头。

## 第三步：建立资产

从台本中整理：

· 角色

· 场景

· 道具

建立对应资产卡。

## 第四步：生成任务

为镜头和资产套用任务模板。

## 第五步：制作人员提交版本

成员进入“我的任务”，上传图片或视频。

系统自动生成：

V001
V002
V003

## 第六步：项目总监审核

项目总监将多个Version加入审核单，集中观看和批注。

## 第七步：版本通过

通过后：

· 更新任务状态

· 设为当前批准版本

· 通知下游负责人

· 下游任务自动解除阻塞

## 第八步：项目交付

最终批准版本进入交付清单。
