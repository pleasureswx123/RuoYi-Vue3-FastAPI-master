# Shot Grid 历史半成品参考评估

## 1. 评估目的

`../参考资料/` 是一个早期 ShotGrid Light 半成品。本项目允许从中提取产品、字段、页面和交互经验，但不继承其技术栈、服务端、数据库实现或工程结构。

本评估回答三个问题：

1. 哪些产品设计值得吸收；
2. 哪些能力需要按照当前基座重新设计；
3. 哪些内容与当前 MVP 冲突，应明确放弃。

## 2. 已核实的参考项目现状

参考项目使用：

- React 19；
- TypeScript；
- Express；
- 独立 PostgreSQL；
- React Context；
- LocalStorage；
- 独立账号和 Cookie 会话；
- 本地文件目录与 NAS 路径。

这些技术和工程决策不进入当前项目。

参考项目真实完成度如下：

| 能力 | 参考项目现状 | 当前项目处理 |
| --- | --- | --- |
| 登录与会话 | 已有独立本地账号、Cookie 会话和登录审计 | 不复用，使用 RuoYi 登录、JWT、Redis 会话和传输加密 |
| 用户管理 | 已有独立 `users` 表和管理员页面 | 不复用，使用 `sys_user` 和现有管理后台 |
| 项目与成员 | 已有部分真实 API 和 PostgreSQL 数据 | 参考交互，使用 `sg_project_member` 重新实现 |
| 镜头、资产、任务 | 主要由 React Context、Mock 和 LocalStorage 提供 | 只参考字段和页面，全部改成真实 FastAPI API |
| 版本与审核 | 页面可交互，但主要修改本地状态 | 只参考审核工作区布局，重做状态机和事务 |
| 文件中心 | 已有上传、NAS 登记、SHA-256、回收站试验 | 参考操作流程，复用平台受保护文件体系 |
| 批注 | 使用 Canvas Data URL 和本地状态 | 重做为结构化批注、毫秒时间点和归一化坐标 |
| 部门沟通 | 有完整聊天式页面 | 当前 MVP 放弃 |
| 外部客户 | 有 `client` 角色设计 | 当前 MVP 不建设客户门户 |
| 测试 | 有少量权限、安全、路径和导入测试 | 参考测试场景，不复用测试框架和代码 |

参考项目 README 已明确说明：账号、项目和成员部分使用数据库，但镜头、资产、任务、版本等业务数据仍主要由 `AppContext` 和 LocalStorage 提供。因此，任何页面效果都不能作为真实业务完成证据。

## 3. 值得采用的产品与交互设计

“采用”表示吸收设计意图，再使用当前技术体系重新实现。

### 3.1 应用框架

- 顶部保留当前项目切换器。
- 顶部提供受权限控制的快捷创建入口：
  - 新建镜头；
  - 导入镜头表；
  - 新建资产；
  - 提交新版本。
- 没有项目时提供明确的首次项目创建引导。
- 多项目时保留清晰的项目上下文，避免操作落入错误项目。

### 3.2 工作台

可参考以下信息卡片和入口：

- 我的制作任务；
- 我的待修改任务；
- 待我审核；
- 今日截止；
- 待审核任务；
- 最近提交；
- 项目交付日期和整体进度。

每个统计必须可以进入对应的真实筛选结果，不能只显示数字。

### 3.3 镜头页面

参考项目对镜头页的探索较完整，可以吸收：

- 搜索镜头编号、描述和台词；
- 按场次、状态、负责人等条件筛选；
- 表格、卡片和故事板三种视图；
- 批量选择和有限的批量编辑；
- Excel/CSV 导入前预览；
- 镜头表导出；
- 镜头详情抽屉；
- 关联资产展示；
- 历史版本带；
- 当前审核版本和审核意见。

批量删除不能直接照搬。正式系统应优先归档，并保护已经产生版本、审核和文件引用的镜头。

### 3.4 资产页面

可以参考：

- 按资产类型切换；
- 资产名称和说明搜索；
- 表格列表与详情面板组合；
- 展示使用该资产的镜头；
- 历史设计版本；
- 最终版本；
- 参考图片；
- 提示词模板；
- Excel/CSV 资产导入与预检查。

资产类型按照当前需求严格收敛为 `Character`（角色）、`Environment`（场景）、`Prop`（道具），不开放“其他”或任意自定义类型。

### 3.5 镜头详情

参考项目把以下信息放在同一工作区，这个方向值得保留：

```text
媒体预览
＋ 镜头基础属性
＋ 关联资产
＋ 历史版本
＋ AI 生成参数
＋ 审核意见
＋ 审核动作
```

但正式实现应避免一个超大组件承担所有逻辑，应拆成媒体、版本、参数、批注和审核动作等领域组件。

### 3.6 审核工作区

以下布局可以作为当前审核页的重要参考：

- 左侧：待审核版本队列；
- 中间：图片或视频审核画布；
- 中间辅助：单版本模式与 A/B 对比；
- 右侧：当前意见、历史意见、AI 参数摘要；
- 底部：退回修改、稍后决定、通过；
- 从时间点意见跳转到播放器位置；
- 创建集中审核单。

需要改进：

- “打分批注”只有明确评分规则后才实现；
- A/B 对比在单版本审核稳定后再进入；
- 审核动作必须调用后端状态机，不能直接改前端数组；
- 审核单必须保存有序版本关系。

### 3.7 文件中心

可以参考的操作模型：

- 上传服务器托管文件；
- 登记 NAS 路径；
- 区分审核文件与工程源文件；
- 选择项目、镜头或资产归属；
- 填写可选版本号；
- 搜索文件名、业务编号或 NAS 路径；
- 按文件用途筛选；
- 下载托管文件；
- 复制 NAS 路径；
- 删除前明确是否可恢复。

正式系统必须改为：

- 复用平台 `fileId` 和业务引用；
- 复用平台 ACL、数据范围、访问日志、回收站和完整性校验；
- 浏览器端不尝试直接打开任意 UNC 路径；
- 文件不能只靠 `entity_type + entity_id` 字符串维持弱引用。

### 3.8 导入体验

参考项目已经体现一些值得保留的导入体验：

- 同时识别中英文表头别名；
- 上传后先预览解析结果；
- 显示可导入数量；
- 对未知类型给出警告；
- 忽略或拒绝缺少关键字段的行；
- 正式提交前显示错误和提示。

正式实现不得：

- 缺少镜头编号时随机生成编号；
- 读取失败后默默填充默认业务数据；
- 在前端直接创建正式数据；
- 发生部分失败时不报告具体行号。

## 4. 可参考的业务字段

以下字段可以进入阶段 0 字段字典评审，但不能直接复制 TypeScript 类型。

### 4.1 项目

- 项目编码；
- 项目类型；
- 画幅；
- 总时长；
- 交付日期；
- 当前阶段；
- 项目总监；
- 项目成员。

镜头总数、已完成数、待审核数、修改中数和未分配数应由后端聚合，不作为前端可写字段。

### 4.2 镜头

- 镜头编号；
- 场次；
- 时长；
- 景别；
- 运镜；
- 镜头描述；
- 台词；
- 关联资产。

当前环节、聚合状态、负责人和最新版本应明确从任务或服务端聚合产生，避免多处可写字段漂移。

### 4.3 资产

- 名称；
- 类型；
- 说明；
- 负责人；
- 参考图片；
- 提示词模板；
- 使用镜头；
- 最终版本。

“使用镜头数”应聚合计算，不单独作为事实字段维护。

### 4.4 任务

- 名称；
- 任务类型；
- 负责人；
- 状态；
- 优先级；
- 截止日期；
- 制作要求；
- 最新版本。

当前项目不采用参考项目的制作环节模板和前置任务模型。每个镜头最多一个 `shot_video` 任务，每个资产制作分项最多一个 `asset_image` 任务；首次分配一名主制作人时创建，改派只修改原任务负责人。

### 4.5 版本 AI 参数

- 模型名称；
- 模型版本；
- 正向提示词；
- 负向提示词；
- 首帧；
- 尾帧；
- 参考视频；
- 时长；
- 分辨率；
- 画幅；
- Seed；
- 运镜模式；
- 生成费用；
- 是否后期处理；
- 原始生成文件；
- 修复后文件；
- NAS 源文件路径。

模型参数属于版本快照。字段应按权限裁剪，费用需要明确币种，文件使用 `fileId`，不能只保存 URL。

### 4.6 审核意见

- 审核人；
- 文字意见；
- 视频时间点；
- 结构化画面标注；
- 是否必须修改；
- 处理状态；
- 制作人员回复；
- 回复时间。

时间点统一使用整数毫秒；不能同时把浮点秒和格式化文本都当作事实来源。

## 5. 必须重新设计的底层实现

以下实现不进入当前项目：

### 5.1 技术与运行时

- React 组件和 Hooks；
- React Context；
- Express API；
- 单端口 Express + Vite 拓扑；
- 独立 TypeScript 服务端；
- 参考项目的 `package.json` 和构建命令。

替代方案由当前项目固定为 Vue 3、Pinia、Axios、RuoYi FastAPI 和现有部署体系。

### 5.2 身份和权限

参考项目重新创建了 `users`、`sessions` 和全局 `role`，与当前 RuoYi 基座重复。

当前项目必须：

- 使用 `sys_user`；
- 使用现有 JWT 和 Redis 会话；
- 使用平台权限码；
- 使用独立项目成员关系表达项目角色；
- 在每个业务接口校验项目成员和资源归属。

### 5.3 状态和持久化

参考项目将镜头、资产、任务、版本等保存到 LocalStorage，并有部分项目状态 JSON 文件。

当前项目必须：

- PostgreSQL 是业务事实来源；
- Pinia 只保存轻量 UI 和共享状态；
- 刷新后从真实 API 恢复；
- 不提供请求失败后回退 Mock 的生产逻辑；
- 不把本地 JSON 文件当作多人业务数据库。

### 5.4 数据模型

参考项目存在以下问题：

- 中文状态直接入库；
- `tasks.entity_type + entity_id` 没有真实外键；
- `versions` 重复维护 `task_id` 和实体归属；
- 版本只保存一个 `file_url`；
- `notes.annotation_data_url` 将整张 Canvas 结果写入数据库；
- 任务模型包含当前项目不需要的前置任务；
- 最终版本没有唯一约束；
- `project_files.entity_id` 后续从 UUID 改成 text，进一步削弱引用完整性；
- 项目统计字段可能与真实数据漂移。

当前项目按照 `AGENTS.md` 的 `sg_` 表、外键、检查约束、单目标单任务约束、平台文件引用和英文状态代码重新实现。

### 5.5 文件与批注

参考项目的 SHA-256、路径限制、回收站和 NAS 登记思路值得参考，但其文件主表和本地目录服务不复用。

批注必须保存可编辑的结构化数据：

```text
versionId
mediaTimeMs
annotationType
normalizedPoints
color
text
sourceWidth
sourceHeight
```

不能把整张图片 Data URL 作为主要批注记录。

## 6. 明确放弃的内容

以下参考功能不进入当前 MVP：

- 部门聊天；
- 专项沟通频道；
- 消息点赞和回复计数；
- 从聊天消息直接提交版本；
- 聊天图片编辑器；
- 独立员工账号管理；
- 独立客户端角色入口；
- 客户门户；
- Gemini 或其他外部 AI 服务调用；
- 自动在服务器创建完整项目目录树；
- 项目业务状态同时保存在 PostgreSQL、LocalStorage 和 JSON 文件。

如果未来需要沟通能力，优先通过任务、版本和审核意见的上下文协作增强，而不是先建设完整聊天系统。

## 7. 可迁移的测试思想

可以将以下测试场景转换到当前测试体系：

- 匿名请求被拒绝；
- 角色不匹配返回 403；
- 非项目成员不能读取项目资源；
- 文件名包含路径分隔符和 Windows 保留字符；
- 文件路径穿越被拒绝；
- 托管文件不能逃逸存储根目录；
- 同一个密码的哈希盐不同；
- 会话 Token 不保存原文；
- 中英文导入表头别名；
- 未知资产类型产生警告；
- 缺少资产名称的行被拒绝；
- 重复场次导入合并或明确报错；
- 分配镜头后只生成一个 `shot_video` 任务；
- 分配资产制作分项后，该分项只生成一个 `asset_image` 任务；
- 缺少制作分项名称可以导入并后续补充，但补齐前不能提交图片版本；
- 每个制作分项只允许一名主制作人，复合制作人值不会被静默拆分或选第一人；
- 改派制作人不会重复生成同类任务；
- 镜头版本业务文件名符合最新冻结的项目、`EP` 集、场次、`S` 镜头、制作人、版本和时间戳规则；
- 资产版本业务文件名符合项目、资产类型、资产名称、制作分项、制作人、版本和时间戳规则；
- 每次上传新版本自动生成一个对应的待审核单。

当前项目还必须新增：

- 并发版本号；
- 并发最终版本；
- 版本不可覆盖；
- 文件引用中的删除保护；
- 跨项目文件与版本引用；
- 批注在不同播放器尺寸下的位置恢复；
- 项目切换后的缓存清理；
- 权限变化后的会话和缓存失效。

## 8. 对当前阶段 0 的影响

参考项目不改变当前实施顺序。阶段 0 仍从领域和 API 契约开始，但可利用它补充以下评审材料：

1. 把参考项目的项目、集、场次、镜头、资产、任务、版本和审核字段加入字段字典候选。
2. 用镜头列表、镜头详情、资产详情和审核页验证 API 是否支持真实页面需要。
3. 用文件中心交互验证平台 `fileId`、业务文件名、业务引用和授权下载接口是否足够。
4. 用导入预览流程定义导入校验和错误报告格式。
5. 用参考项目暴露的问题检查单目标单任务约束、版本唯一性、自动审核单、状态机和批注协议。
6. 对每个采用的设计标记“产品参考”，重新给出 Vue/FastAPI/PostgreSQL 实现方案。

阶段 0 的最终契约不能以参考项目代码为准；正式事实来源仍是当前 `需求.md`、`AGENTS.md`、已确认的 RuoYi 基座能力和新建的接口设计文档。
