# Shot Grid 后端联调清单

## 1. 结论与使用边界

- 核对日期：2026-08-11。
- 静态核对后端 `module_shot_grid` 的 Controller、Service、DAO、DO、VO，前端 `src/api/`、`src/views/`、`src/components/`，并核对两端测试目录。
- **本清单是源码与契约盘点，不是联调通过报告。**本次未启动 FastAPI、PostgreSQL、Redis、文件服务、真实 NAS 或浏览器 E2E。
- 表中“源码完成”只表示存在端到端代码分层；所有条目的交付结论仍是 **源码完成，待集成/E2E**。单元测试仅是独立维度，不能替代真实联调或浏览器 E2E。

## 2. 通用真实契约

所有业务路由要求 `PreAuthDependency` 并逐接口检查 `shotgrid:*` 平台权限；项目资源还经过项目访问依赖。VO 使用 camelCase alias。普通对象成功响应使用 `data`，分页使用顶层 `rows/total`；领域异常保留真实 HTTP 状态及稳定 `errorKey`，认证、授权与 FastAPI 422 不保证相同错误 envelope。

项目、资源、需求、审核动作等写请求使用 `lockVersion` 或幂等键防止静默覆盖。平台权限、项目实时成员范围和文件 ACL 是不同门禁，任一门禁通过都不能绕过其他门禁。

## 4. 已确认的前后端契约差异

1. `resource_controller.py` 为集、场次、镜头、资产、制作分项统一注册顶层项目路径，归档方法为 `PUT`；前端四类资源当前归档使用 `POST`。
2. `scenes.js` 使用 `/episodes/{episodeId}/scenes` 列表/创建路径，而当前通用后端资源路由是 `/scenes`；需要选择并冻结一个契约，不能靠 Mock fallback。
3. `assets.js` 使用 `/assets/{assetId}/items` 管理制作分项，而当前后端通用资源路由使用 `/asset-items`；需要统一请求路径及制作分项详情/归档行为。
4. 上述差异修正前，相应页面只能记录为“前端源码部分完成”，不能写成联调成功。

## 5. 最小真实联调顺序

1. 启动 PostgreSQL、Redis、FastAPI 与业务前端，使用非管理员 director 和 creator 测试账号。
2. 验证登录、导航、项目创建、存储状态和成员权限；再验证集/场次/镜头/资产 CRUD 的实际 HTTP method 和 envelope。
3. 执行镜头导入、资产导入、需求候选与绑定/关闭；验证事务回滚、幂等重放和 409 乐观锁冲突。
4. 分配并开始镜头/制作分项任务，上传受保护文件，初始化版本提交并等待受控 NAS 发布完成。
5. 验证审核单、意见/回复和 `reject → 新版本 → approve`，并用并发请求确认只存在一个 final。
6. 验证工作台、搜索、文件发现、Range 预览/下载、ACL deny 以及非成员按 ID 越权的负向路径。
7. 最后运行真实浏览器 E2E；API 成功、单元测试、构建或页面打开均不能替代此步骤。
