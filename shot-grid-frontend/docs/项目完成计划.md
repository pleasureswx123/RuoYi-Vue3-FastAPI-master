# Shot Grid 项目完成计划

## 1. 计划目的

本计划用于把《需求.md》中的 ShotGrid 轻量化产品方案交付为可运行、可验证、可继续扩展的 AI 影视项目管理系统。

计划覆盖：

- `shot-grid-frontend` 业务前端；
- `ruoyi-fastapi-backend` Shot Grid 业务接口；
- PostgreSQL 表结构与迁移；
- RuoYi 登录、用户、权限、文件和传输加密能力复用；
- 图片、视频、版本、批注和审核链路；
- 自动化测试、真实 E2E、部署和运维文档。

本计划不以“页面已经画完”作为完成标准。只有真实数据、权限、文件、状态流转和刷新恢复均通过验证，相关功能才算完成。

## 3. 完成定义

项目完成必须同时满足以下条件。

### 3.1 产品范围

- 六个一级页面可用：工作台、项目、镜头管理、资产库管理、版本审核、文件与 NAS。
- 项目内部页面可用：概况、集与场次、镜头、资产、审核、成员。
- 任务详情、镜头详情、资产详情和版本审核形成连贯业务路径。
- 《需求.md》列出的 14 项 MVP 能力全部有真实实现和验收证据。
- “第一版暂时不做”的能力没有被偷偷并入 MVP。

### 3.2 数据闭环

```text
项目与成员
→ 集、场次、镜头和三类资产
→ 分配制作人并创建唯一视频或图片任务
→ 线下制作后上传文件
→ 自动创建不可覆盖版本、规范业务文件名和单版本审核单
→ 对指定版本批注
→ 退回或通过
→ 退回后生成下一版本，或确认最终版本并完成任务
→ 可选加入人工批量审核单
→ 刷新后仍可恢复完整状态
```

### 3.3 工程质量

- 前端技术栈和工程组织参考 `ruoyi-fastapi-frontend`。
- 后端遵循现有 Controller → Service → DAO → DO/VO 分层。
- PostgreSQL 结构变更同时通过 SQLAlchemy DO、Alembic 迁移和 `ruoyi-fastapi-backend/sql/ruoyi-fastapi-pg.sql` 交付。
- 前端和后端都存在可重复执行的检查及测试命令。
- 核心链路存在真实集成测试和端到端测试。
- 生产配置不包含示例密码、私钥、Token 或默认密钥。

### 3.4 交付边界

以下结果不能单独作为项目完成证据：

- 静态原型或设计稿；
- Mock 数据可以操作；
- Swagger 中存在接口；
- 数据表已经建立；
- 前端构建成功；
- 服务健康检查成功；
- 只完成单个角色或单条成功路径；
- 只在不刷新页面时看起来正常。

## 4. 固定技术与产品决策

在用户没有明确变更前，以下决策作为计划基线：

- 业务前端是独立应用，不取代 `ruoyi-fastapi-frontend` 管理后台。
- 前端使用 Vue 3、Vite、Vue Router、Pinia、Axios、Element Plus、Sass 和 npm。
- 依赖版本、构建配置、认证和请求基础设施优先参考 `ruoyi-fastapi-frontend`。
- 后端复用现有 RuoYi FastAPI 服务，不另建第二套认证服务。
- 用户复用 `sys_user`，项目内身份通过项目成员关系表达。
- Shot Grid 新业务默认仅支持 PostgreSQL。
- 业务表使用 `sg_` 前缀。
- 业务 API 使用 `/shot-grid` 前缀。
- 权限码使用 `shotgrid:<resource>:<action>` 格式。
- 文件使用平台受保护文件和 `fileId` 引用机制。
- MVP 不交付客户独立门户；外部审核只保留未来兼容设计。

如果正式实现采用不同的 API 前缀、权限码或表名，必须先形成明确决策，并同步更新 `AGENTS.md`、本计划和接口文档。

## 16. 关键风险与控制措施

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 先做全量页面、后定接口 | 字段和状态反复返工 | 阶段 0 先冻结契约 |
| 直接复用全部 `/getRouters` | 业务端加载管理端菜单失败或越权 | 使用 `/shot-grid/navigation` 范围菜单和本地路由白名单 |
| 直接使用代码生成器的 CRUD 完成核心流程 | 绕过项目权限、状态机和跨表事务 | 生成器只产出骨架，核心 Service、状态机和测试人工实现 |
| 复用现有用户 Excel 直接落库模式 | 多表导入半成功且无法预览冲突 | 使用批次、preview/commit、Redis Token、全事务和幂等 |
| 镜头导入时隐式创建资产 | 拼写错误产生重复正式资产和错误任务 | 先建立待匹配需求，资产后导入只匹配唯一候选 |
| 重建用户表 | 两套账号和权限漂移 | 强制复用 `sys_user` |
| 文件只保存 URL | URL 失效且无法治理引用 | 保存 `fileId` 并复用业务引用 |
| 大视频直接上传后同步处理 | 请求超时、资源耗尽 | 冻结大小限制并采用异步媒体处理 |
| 前端生成版本号 | 并发出现重复版本 | 后端事务生成并添加唯一约束 |
| 标注保存像素坐标 | 播放器缩放后位置漂移 | 使用归一化坐标和自然尺寸 |
| 状态只在前端流转 | 可绕过权限和流程 | 后端状态机、事务和审计 |
| NAS 路径直接 `window.open` | 浏览器拦截或安全风险 | MVP 查看/复制，桌面协议另立项目 |
| 只因 Worker 源码或临时目录测试通过就启用生产 NAS | 服务账号权限、共享 ACL、UNC 语义和故障恢复未验证 | 默认关闭 Worker；使用正式 Windows 账号和隔离 UNC 根目录完成 E2E 后再显式启用 |
| 把软超时当作可中止 SMB I/O | 租约释放后旧线程仍可能继续写目录 | 超时只做诊断并继续心跳；等待物理 I/O 退出后再处理租约结果 |
| 外部审核提前进入 MVP | 匿名授权和数据隔离扩大范围 | 当前只交付内部审核 |
| PostgreSQL 迁移链与初始化 SQL 不一致 | 新环境和升级环境结构漂移 | 每个结构变更同时提交并核对 Alembic 与 PostgreSQL 初始化 SQL |
| 资产来源行键依赖文件摘要和物理坐标 | 工作簿重存或移动行后，未命名制作分项可能被当作新行 | 后续模板引入稳定 `rowUid`，或建立疑似重复提示与人工治理；当前不宣称跨文件逻辑幂等 |
| Mock 请求失败回退 | 掩盖真实后端不可用 | 生产代码禁止自动回退 Mock |

## 17. 阶段门禁

每个阶段完成时进行一次门禁评审：

1. 需求范围是否仍与 `需求.md` 一致。
2. 是否违反 `AGENTS.md` 的数据和权限不变量。
3. 前后端契约是否已同步。
4. PostgreSQL 迁移是否可重复执行。
5. 成功、失败、无权限和并发路径是否有验证。
6. 是否保留用户已有变更且没有提交敏感文件。
7. 实际验证结果是否与交付说明一致。

门禁未通过时，不得将该阶段标为完成。

## 19. 建议立即开始的工作

镜头、资产样表参数，项目/成员/集/场次/镜头/资产/制作分项普通管理、两类 Excel 预检与提交、独立任务、主文件版本和 `auto_single` 审核后端，以及两个默认关闭的 NAS Worker 已完成代码实现。下一步按以下顺序继续：

1. 使用正式 Windows Worker 服务账号和隔离 UNC 根目录完成 NAS/AD/共享 ACL、项目初始化、动态目录、失败重试与 Leader 接管验收；验收前保持 `SHOT_GRID_STORAGE_WORKER_ENABLED=false`。
2. 确认同域不同路径部署、登录页复用和登录态共享方式。
3. 初始化独立业务前端工程，并接入真实登录、用户信息与 `/shot-grid/navigation`。
4. 实现资产需求人工处理与 `manual_batch`，并补齐当前任务—版本—自动审核后端的 PostgreSQL 集成验证；继续保持 `project → task/submission → version → auto_single review list → note` 锁序。
5. 在正式 Windows Worker 服务账号和隔离 UNC 根目录验证版本临时写入、摘要校验、无覆盖发布、失败重试、租约接管与业务下载授权，再完成第一批浏览器可交付闭环：

```text
真实登录
→ 项目列表
→ 创建项目
→ 添加项目成员
→ 导入一个最小镜头表并生成集、场次、镜头和待匹配资产需求
→ 导入一个最小资产表并自动匹配唯一需求
→ 刷新后数据与权限保持正确
```

该闭环通过后，把已经实现的任务、版本和自动审核 API 接入业务前端；媒体缩略图/代理和人工批量审核单另按未完成项推进。
