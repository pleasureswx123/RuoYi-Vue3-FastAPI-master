# Shot Grid 非生产 SMB/NAS 验收手册

本手册用于在**独立非生产共享**上验收 Shot Grid 目录初始化与版本发布。测试人员必须把真实 SMB 结果与临时本地目录单元测试分开记录；未完成本手册的真实共享步骤时，只能报告“源码/单元测试已验证”。

## 1. 前置安全门禁

1. 在 NAS 创建专用共享和专用目录，例如 `shot-grid-acceptance`。禁止复用生产共享。
2. 创建专用服务账号，只授予该目录的列出、创建目录、读、写、重命名和删除临时文件权限；不得授予共享管理、其他目录读取或生产权限。
3. 凭据放入操作系统凭据存储或部署平台 Secret。数据库中的 `credential_ref` 只能保存引用名，日志、截图、用例和报告不得记录用户名、密码或带凭据 URI。
4. Windows Worker 使用专用服务身份访问 UNC。Linux Worker 应由系统管理员用 CIFS 将共享挂载给该服务身份；挂载选项和 Secret 文件权限须另行评审。不要把密码直接写在命令行或仓库文件中。
5. 为测试目录设置清晰的清理期限，并在验收后由同一管理员按精确范围清理。

## 2. 注册白名单根并启动独立 Worker

通过受控管理流程在 `sg_storage_root` 注册唯一测试根，至少填写独立的 `root_code`、`protocol=smb_unc`、规范化 `unc_root_path`、不含凭据的 `credential_ref` 引用、`root_status=enabled` 和健康探测结果。不要在工单或报告中粘贴完整 UNC 根路径。

执行 I/O 时，代码必须重新读取当前 `sg_storage_root.unc_root_path`，将项目相对路径和业务相对路径拼接后交给 `ShotGridStoragePathService.resolve()`；完整项目路径快照不能作为执行根。用 `..`、绝对路径、保留名和不同共享前缀进行负向测试，均应在 I/O 前拒绝。

目录操作 Worker 必须与 Web 服务分开部署，每个进程使用唯一且不含主机凭据的标识：

```bash
cd ruoyi-fastapi-backend
python module_shot_grid/storage_worker.py --worker-id sg-storage-acceptance-01 --idle-seconds 1
```

以两个独立进程验证并发领取时，第二个进程改用 `sg-storage-acceptance-02`。停止进程后再启动用于验证租约接管；不要在 Web Worker 中创建临时线程替代此部署单元。

## 3. 正向用例

### 3.1 项目初始化

创建一个只用于验收的项目，等待初始化操作成功，然后在共享端确认以下目录存在：

```text
ASSET/Character
ASSET/Environment
ASSET/Prop
VIDEO
```

重复对账必须保持幂等，且不能改写目录内预先放置的哨兵文件。

### 3.2 版本发布

分别用受控小型视频和图片样本验证：

1. 平台私有上传完整，平台记录的文件大小和 SHA-256 与源文件一致。
2. Worker 只在目标目录创建 `.sgtmp-*.part` 临时文件，写入后刷新并核对 SHA-256。
3. 临时文件和目标文件位于同一项目共享、同一文件系统，并通过原子 `rename` 发布；不得用跨文件系统复制冒充原子发布。
4. 正式短事务一次写入版本、版本文件、文件引用、自动审核单、任务状态和操作日志。
5. 成功后目标文件摘要等于源摘要，临时文件不存在，submission 为 `committed`。

## 4. 故障与并发矩阵

每个用例都记录操作 ID/submission ID 等非敏感标识、预期、实际状态、数据库结果和共享端结果：

| 用例 | 注入方式 | 必须确认 |
| --- | --- | --- |
| 共享离线 | 在领取前断开测试共享或防火墙 | 返回净化的不可达错误；不泄露根路径/凭据；可按退避重试 |
| 权限不足 | 临时移除测试账号写或重命名权限 | 返回权限错误；不产生正式文件；恢复权限后仅单次重试 |
| 路径冲突 | 占用项目路径或提交越界/保留名 | 冲突或路径校验失败；不访问项目范围外路径 |
| 文件已存在 | 预置同名同摘要及同名异摘要文件 | 同摘要幂等；异摘要终止且绝不覆盖 |
| Worker 中途退出 | 写临时文件前后分别终止进程 | 租约内不被重复领取；超时后复用原操作/submission |
| 租约超时 | 暂停 Worker 超过配置租约 | 另一 Worker 可接管；旧 Worker 不能结算已失租约操作 |
| 多 Worker 领取 | 同时运行两个唯一 Worker | PostgreSQL 行锁与 `SKIP LOCKED` 保证同一时刻仅一个所有者 |
| 数据库正式提交失败 | 在 NAS 发布后注入短事务失败 | 整体回滚并恢复为 `published`；重试不重新分配版本号或文件名 |

完成故障注入后必须恢复共享权限和网络，并核对没有残留临时文件。破坏性注入只允许作用于专用测试项目。

## 5. 管理接口安全验证

使用管理员身份分别调用项目诊断、失败操作的单次重试和项目目录对账，并检查 HTTP 响应、应用日志、数据库错误摘要及审计记录：

- 不出现 `credential_ref`、完整 UNC 根、目标相对路径、Worker 标识、用户名或密码。
- 单次重试只改变指定失败操作；处理中或成功操作返回不可重试。
- 对账操作从数据库项目绑定生成目标，只检查/创建该项目目录，不接受客户端路径，也不读取相邻项目。
- 非管理员调用被后端角色依赖拒绝；不能把前端按钮隐藏当作权限验证。
